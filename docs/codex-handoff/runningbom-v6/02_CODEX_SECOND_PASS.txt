0. 최상위 목표
======================================================================

너는 Claude Code가 만든 러닝봄 V6 결과를 믿지 않고 처음부터 검증하는 2차 책임 개발자다.
보고서만 작성하는 리뷰어가 아니라, 결함을 실제 코드에서 재현하고 직접 수정하고 테스트하고 커밋·PR까지 남겨야 한다.

V6의 핵심 제품 목표:

- 사용자가 3분을 뛰든 몇 시간을 뛰든, 직접 정한 시간·거리·프로그램·오픈엔드 조건으로 실행 가능
- 밀착 코치와 풀토크 코치를 선택하면 러닝 내내 사람 코치처럼 자연스럽게 계속 대화
- 머리부터 발까지 자세·힘 빼기·리듬·호흡·마음가짐을 순환 코칭
- 실제 자세를 볼 수 없으므로 감지했다고 거짓말하지 않음
- 존댓말·반말, 코치 성격, 말의 양, 집중 주제, 목소리, 메트로놈을 독립적으로 선택
- 음악·팟캐스트·통화·Bluetooth·화면 잠금에서도 기록과 오디오 상태가 깨지지 않음
- 메트로놈은 장시간에도 박자가 밀리지 않는 오디오 시계 기반
- 기존 기록·프로그램·저장 키·앱 식별자·보안·CI를 깨지 않음

100만 다운로드와 러닝 앱 1등은 사업 목표이지 완료를 보장하는 문구가 아니다.
증거 없이 “완벽”, “사람 목소리 완성”, “무제한 실행 검증 완료”라고 보고하지 마라.

5. 실행시간·오픈엔드 파괴 테스트
======================================================================

실제 compiler·runtime·simulator로 다음을 생성하고 실행한다.

3분, 5분, 10분, 20분, 30분, 49분, 50분, 51분, 60분, 90분,
119분, 120분, 121분, 180분, 360분, 720분, open-ended 12시간 시뮬레이션.

각 실행에서 기록:

- 시작·워밍업·안정·마무리 단계
- 발화수
- 실제 합성 오디오 총시간
- speech occupancy
- 문장 사이 median·p95·max gap
- 정확한 반복
- 의미상 반복
- false progress·false ending
- queue peak
- memory peak
- cache size
- generation time
- pause/resume
- 앱 재시작 복구
- 실행 중 +5분, +10분, +30분
- 사용자의 “마무리 시작”
- 즉시 종료

필수 불변조건:

- 50분만 정상이고 49·51분이 깨지면 안 됨
- open-ended에서 사용자가 마무리를 누르기 전 종료성 문구 없음
- 6시간 뒤 warmup 문구 재등장 없음
- queue·memory가 실행시간에 따라 무한 증가하지 않음
- 12시간 시뮬레이션이 O(n²)로 느려지지 않음
- duration integer overflow 없음

문제는 직접 수정한다.

7. 밀착 인간 코치 계약
======================================================================

풀토크 코치는 단순히 9초마다 랜덤 문장 하나를 재생하는 기능이 아니다.
다음 상태를 가진 대화 엔진이어야 한다.

- 현재 자세 주제
- 진행 중인 설명 thread
- 앞에서 약속한 후속 멘트
- 최근 사용 문장·개념·문장 시작·어미
- 전신 스캔 위치
- 마지막 전신 리셋
- 사용자가 싫다고 한 주제
- 코치 성격·말투·밀도
- 현재 훈련 단계와 목적

콘텐츠 단위:

- 짧은 자세 cue
- 연결 문장
- 20~60초 교육 블록
- 30초~3분 이야기 블록
- 스스로 확인하게 하는 질문
- 앞의 말을 다시 잇는 callback
- 주제를 자연스럽게 바꾸는 transition

한 번에 한 가지 자세에 집중한다.
계속 말한다는 이유로 매 문장마다 머리→발→어깨→호흡으로 튀면 안 된다.

권장 순환:

머리·시선·턱 → 목·어깨 → 손·팔 → 몸통·골반 → 엉덩이·무릎 →
발목·발 → 보폭·리듬 → 호흡 → 전신 연결.

기술 문장만 계속 강요하지 않는다.
자세·리듬·훈련 목적·진행·마음가짐·이야기의 비율을 모드별로 검증한다.

금지 표현과 로직:

- “이 자세면 부상을 예방한다”
- “아파도 뛰어”
- “통증을 무시해”

센서가 없을 때 허용되는 방식:

- 조건형: “발가락에 힘이 들어갔다면 풀어.”
- 확인형: “어깨가 올라가 있지 않은지 확인해.”
- 감각형: “발이 몸보다 멀리 나가면 보폭을 조금 줄여.”
- 실험형: “속도는 그대로 두고 걸음만 3% 빠르게 시험해.”

케이던스:

- 개인 기준 우선
- +3%, +5%를 우선 실험
- +7%, +10%는 고급·검수 조건
- steps per minute와 strides per minute 혼동 금지
- 불편하면 기준값으로 복귀
- 부상 예방 보장 금지

착지:

- 자연 착지 존중
- 조용하고 부드러운 착지는 감각 실험으로만
- 앞꿈치·뒤꿈치 전환 강요 금지

11. Android·iOS 오디오 포커스
======================================================================

Android:

- 전체 세션에 AUDIOFOCUS_GAIN을 잡아두지 않음

- 음악은 may-duck 후보
- 팟캐스트·오디오북은 pause 정책
- onDone/onError/onStopped에서 즉시 abandon
- delayed focus 처리
- permanent loss 후 자동 재개 금지
- transient interruption 복구
- 통화·알람·지도 안내
- 이어폰 해제·audio route change
- MediaSession·notification action

현 코드에 focus leak이나 세션 전체 독점이 남으면 직접 수정한다.

이 경우 실기기 검증:

- Spotify
- YouTube Music
- Apple Music
- 팟캐스트
- 오디오북
- 전화
- 알람
- 지도 안내
- Bluetooth 이어폰
- 차량 Bluetooth
- 스피커
- 화면 잠금

- AVAudioSession category·mode·options
- spoken audio interrupt
- music duck
- notifyOthersOnDeactivation

- route change
- Bluetooth
