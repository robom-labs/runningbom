# RUNNINGBOM V7 — SIMPLE SURFACE, DEEP CAPABILITY
## 러닝봄 기능 보존형 전면 UX·정보구조·스포티 디자인·코드구조 재설계 실행 프롬프트
### 문서 버전: 7.0.0
### 대상: Claude Code 또는 Codex
### 대상 저장소: robom-labs/runningbom
### 작성 기준일: 2026-07-28

이 문서 전체를 처음부터 끝까지 전문으로 읽고 실제 구현·테스트·시각검증·원자 커밋·PR까지 수행하라.

이 작업은 기능을 줄이는 작업이 아니다.

> **현재 러닝봄의 기능은 전부 살리되, 처음 보이는 화면은 단순하고, 사용자가 필요한 순간에만 해당 기능이 자연스럽게 펼쳐지도록 다시 설계한다.**

기능을 삭제해서 단순해 보이게 만들면 실패다.
모든 기능을 첫 화면에 늘어놓아 “다 있습니다”라고 보여 주는 것도 실패다.

최종 제품은 다음 경험을 제공해야 한다.

1. 처음 켠 사람은 10초 안에 오늘 무엇을 할지 안다.
2. 추천 러닝은 한 번 눌러 시작한다.
3. 직접 고르는 러닝은 두세 번 안에 시작한다.
4. 대회·러닝화·러닝 지식은 하나의 “찾기” 안에서 명확히 나뉜다.
5. 기록·분석·배지·보관함·프로필·설정은 “나” 안에서 찾는다.
6. 설정 첫 화면에는 세부 조절값이 쏟아지지 않는다.
7. 기존 40개 훈련계획, 103개 일회성 훈련, 40개 도전, 20개 보조 프로젝트, 대회, 러닝화, 배지, 커뮤니티 준비 코드, 음성코치, 메트로놈, GPS Preview 기능은 모두 새 구조에서 도달 가능하다.
8. 사용자는 기능 수를 느끼지 않고, 필요할 때 기능의 깊이를 느낀다.

# 0. 지침 우선순위

실행 정책의 우선순위:

1. `ROBOM_HQ_ULTIMATE_CONTROL_TOWER_PROMPT_v1.4.0` — 궁극의 로봄 v1.4
2. 사용자의 현재 명시적 지시
3. 실제 설치 앱·Production·Google Play·EAS·서명·실기기 상태
4. 실행 시점의 최신 `origin/main`, 실제 코드, 실제 테스트와 빌드
5. 이 V7 문서
6. V6 및 과거 V1~V5 문서와 오래된 PR

V7과 과거 문서가 충돌하면 다음을 따른다.

- 기록 무결성·보안·저장 호환·권한 보호는 기존 완료분을 유지한다.
- 정보구조·화면 노출·디자인·설정 구조는 V7을 우선한다.
- 최신 코드가 과거 문서보다 앞서면 최신 코드를 사실 정본으로 사용한다.
- 최신 코드에 실제 UX 결함이 있으면 재현 증거를 만든 뒤 수정한다.

# 1. 절대 하드룰

## 1.1 기능 보존

다음을 삭제하지 않는다.

- 음성 코치와 V6 코치 성격·말투·밀도·긴 이야기
- 시간·거리·오픈엔드 러닝
- GPS Preview 추적, 자동 멈춤, 구간, 경로
- 40개 이상의 훈련계획
- 100개 이상의 일회성 훈련
- 도전
- 보조 프로젝트
- 목표 대회
- 대회 접수 알림
- 대회 달력·필터·상세
- 러닝화 탐색·추천·비교·저장
- 러닝 지식
- 활동 기록·통계·최고기록
- 배지
- 월간 지도
- 프로필
- 데이터 내보내기·삭제
- 계정·연동 기반 코드
- 커뮤니티·크루·리그 준비 코드
- 도움말·개인정보·앱 정보
- 메트로놈·케이던스
- 기존 딥링크·알림 진입
- 기존 저장 데이터

기능은 “삭제”가 아니라 다음 중 하나로 처리한다.

```text
PRIMARY            항상 보이는 핵심 기능
CONTEXTUAL         관련 상황에서 자동 노출
SECONDARY          해당 허브 안에서 한 번 더 들어가면 노출
ADVANCED           상세 설정 안에서만 노출
FEATURE_GATED      준비가 끝난 경우에만 노출
DEVELOPER_ONLY     일반 사용자에게 숨기고 진단 화면에서만 노출
```

## 1.2 사용자 데이터·ID 보호

- 기존 저장 키 변경 금지
- 기존 활동 ID 변경 금지
- 기존 프로그램 ID와 진행 기록 변경 금지
- 기존 배지 ID 변경 금지
- 대회·러닝화 ID 변경 금지
- 패키지·번들 ID 변경 금지
- 딥링크를 깨뜨리는 파괴적 route rename 금지
- migration 없이 lastTab·route 값을 무효화하지 않음
- forward-only migration
- migration 전 backup
- rollback 가능

## 1.3 현재 Play 심사 보호

- 새 Android 권한을 Production에 임의 추가 금지
- 새 foreground service type 임의 추가 금지
- 새 네이티브 의존성을 심사 중 artifact에 섞지 않음
- 현재 Production과 Preview의 기능 차이를 보존
- 새 권한·native dependency가 필요하면 `POST_REVIEW` branch와 feature gate
- 실제 Play Console 변경은 CEO 승인 전 금지

## 1.4 UX 진실성

- 없는 기능을 메뉴에 “준비 중” 카드로 계속 홍보하지 않음
- 비활성 기능은 기본 탐색에서 숨김
- 실제 사용자가 없는 커뮤니티를 핵심 메뉴로 노출하지 않음
- 실제 데이터가 없으면 가짜 차트·가짜 후기·가짜 사람 금지
- 사용자가 이해하지 못할 내부 용어 금지
- “완벽”, “AI가 알아서”, “최적”을 증거 없이 쓰지 않음
- 기술 정보·SHA·스키마를 일반 설정 첫 화면에 노출하지 않음

# 3. 외부 앱·플랫폼에서 가져올 원칙

실행 시점에 공식 문서를 다시 확인한다.
디자인을 복사하지 말고 정보구조와 행동 원칙만 가져온다.

## 3.1 Nike Run Club

공식 출처:

- https://www.nike.com/running/training-plans/
- https://www.nike.com/jp/help/a/nrc-plan
- https://about.nike.com/ko/newsroom/releases/nike-run-club-app-delivers-new-features-to-prepare-support-and-empower-runners

가져올 원칙:

- 훈련계획 수와 guided run 수가 많아도, 사용자는 현재 plan과 이번 run을 먼저 본다.
- 각 계획은 주간 목표와 각 run의 목적을 설명한다.
- 계획 회차에서 바로 audio-guided run을 시작한다.
- 콘텐츠 라이브러리의 크기를 홈에 모두 진열하지 않는다.
- coaching, plans, run, activity를 명확한 목적지로 구분한다.

가져오지 않을 것:

- Nike의 아이콘·색·카피·레이아웃 복제
- 현재 러닝봄에 없는 위치공유·웨어러블을 있는 것처럼 표시

## 3.2 Runna

공식 출처:

- https://support.runna.com/
- https://support.runna.com/en/articles/8159780-setting-up-and-managing-your-audio-cues

가져올 원칙:

- 설정은 관련 행동 안에서 찾을 수 있어야 한다.
- 오디오 cue 간격·볼륨 같은 값은 실제 run recording 맥락에서 변경 가능하다.
- 현재 plan과 week가 첫 화면의 중심이다.
- 고급값을 global settings에 전부 펼치지 않는다.

## 3.3 Android·Apple 내비게이션

공식 출처:

- https://developer.android.com/design/ui/mobile/guides/layout-and-content/app-anatomy
- https://developer.android.com/guide/navigation
- https://developer.android.com/guide/navigation/integrations/ui
- https://developer.apple.com/design/human-interface-guidelines/tab-bars

가져올 원칙:

- 탭은 최상위 목적지 이동에 사용한다.
- top-level과 child destination을 구분한다.
- child screen은 back/up을 보여 준다.
- tab 수는 적을수록 단순하다.
- 동일한 top-level 기능을 drawer와 tab에 동시에 중복하지 않는다.
- Help·Privacy 같은 기능은 secondary navigation 또는 settings에 둔다.

## 3.4 Samsung Health

공식 지원 흐름에서 가져올 원칙:

- 운동 시작 시 목표 종류를 한 번에 전부 설명하지 않는다.
- 현재 activity를 고른 뒤 시간·거리 같은 목표를 작은 흐름으로 설정한다.
- 빠른 시작과 세부 설정을 분리한다.

# 4. V7 제품 원칙

## 4.1 표면은 단순하고 깊이는 유지

```text
첫 화면: 3~5개 목적
두 번째 화면: 해당 목적의 핵심 선택
세 번째 화면 또는 sheet: 고급 기능
```

## 4.2 기능은 장소가 하나

같은 기능을 여러 메뉴에 중복시키지 않는다.

예:

- 러닝 시작은 `달리기`
- 계획과 훈련 라이브러리는 `훈련`
- 대회·러닝화·지식은 `찾기`
- 기록·분석·배지·저장 목록은 `나`
- 설정은 `나 > 설정`
- 공유는 `러닝 완료`와 `나 > 공유 기록`
- 도움말은 `설정 > 도움말`

홈은 기능 목록이 아니라 오늘 행동과 맥락을 보여 준다.

## 4.3 한 화면에 하나의 주 행동

첫 viewport에는 primary CTA가 최대 하나다.

## 4.4 점진적 공개

- 기본값은 추천값
- 고급값은 접기
- 기술 내부값은 일반 사용자에게 숨김
- 사용자가 관련 행동을 하는 순간에만 해당 설정 진입 제공

## 4.5 상태가 우선

비어 있는 기능보다 현재 사용자의 상태를 먼저 보여 준다.

```text
오늘 할 것
현재 plan
목표 대회
이번 주
최근 완료
```

# 5. 새 최상위 정보구조 — 5개 목적지

Bottom Navigation은 정확히 다섯 개다.

```text
오늘
훈련
달리기
찾기
나
```

## 5.1 오늘

역할:

- 오늘 할 행동 한 개
- 이번 주 진행
- 목표 대회·다음 일정
- 최근 완료 요약

넣지 않을 것:

- 러닝화 순위 5개
- Q&A 전체
- 배지 전체
- 모든 접수 중 대회
- 상세 목표 편집
- 설정
- 준비 중 커뮤니티

## 5.2 훈련

상단 segmented navigation:

```text
오늘
내 계획
라이브러리
```

하위 secondary:

```text
박자 맞추기
도전
챙길 것
일정
```

## 5.3 달리기

Bottom tab의 가운데 강조 목적지다.

중요:

- tab을 누르면 즉시 기록 시작이 아니라 `Run Setup` destination으로 이동
- 탭은 navigation 역할을 지킨다
- setup에서 큰 Start를 한 번 누름
- active run에는 bottom navigation을 숨김

## 5.4 찾기

상단 segmented navigation:

```text
대회
러닝화
러닝 지식
```

필요하면 `저장한 것` shortcut 제공.

## 5.5 나

첫 화면:

- 이번 주·이번 달 간단 요약
- 최근 활동
- 성취
- 저장한 대회·신발
- 프로필
- 설정

하위:

```text
활동 기록
분석
배지
보관함
프로필
설정
```

# 7. 새 내비게이션 셸

## 7.1 제거

runtime에서 제거:

- top-level 화면의 햄버거 버튼
- DrawerMenu
- drawer + bottom tabs 동시 사용
- 같은 목적지의 중복 global entry
- top-level과 child의 동일 header

코드는 migration 완료 후 삭제한다.
초기 단계에는 legacy adapter를 둘 수 있다.

## 7.2 새 shell

후보 구조:

```ts
type PrimaryDestination =
  | 'today'
  | 'training'
  | 'run'
  | 'explore'
  | 'me';
```

Bottom tab:

- 오늘
- 훈련
- 달리기
- 찾기
- 나

중앙 `달리기`는 시각적으로 조금 강조하지만, navigation destination이다.

## 7.3 Header 규칙

Top-level:

- 햄버거 없음
- Today는 wordmark 또는 인사
- 다른 top-level은 짧은 제목
- 필요한 오른쪽 action 하나만

Child screen:

- 왼쪽 back
- 현재 title
- 오른쪽 optional action
- bottom tab은 child의 parent destination 상태를 유지

Modal / active run:

- self-contained
- bottom tab 숨김
- 명확한 닫기 또는 완료

## 7.4 Back stack

기존 수동 `historyRef`를 계속 쓰더라도 다음을 보장한다.

- top-level tab을 바꾸면 각 tab의 child state 복원
- child에서 back은 parent로
- Android back predictability
- deep link에서 back은 적절한 parent
- 알림 진입에서 back은 대회 목록
- active run 중 accidental back 방지
- lastTab legacy value migration

가능하면 최신 안정적인 React Navigation 구조를 검토하되, 새 dependency가 현재 출시 계약을 위험하게 하면 custom typed navigation을 개선한다.

# 8. 새로운 대표 UI 개념 — RUN RAIL + RUN DOCK

기존 앱과 다른 고유 구조를 만든다.

## 8.1 Run Rail

오늘 화면에 얇은 vertical 또는 horizontal progress rail을 둔다.

```text
지금
↓
이번 주
↓
목표 대회
```

각 node는 작은 상태와 한 줄 의미만 보여 준다.

예:

```text
지금        25분 편하게 달리기
이번 주     3회 중 1회 완료
목표 대회   서울 10K · 42일 남음
```

사용자가 node를 누르면 상세로 들어간다.

Rail은 세 개의 큰 카드 대신 하나의 연결된 맥락을 만든다.
과도한 타임라인 장식은 금지한다.

## 8.2 Run Dock

달리기 setup의 첫 화면:

```text
오늘 추천
25분 편하게 달리기

시간       25분             >
코치       러닝메이트·밀착   >
박자       사용 안 함        >

[달리기 시작]

다른 훈련 고르기
고급 설정
```

각 row를 누르면 한 가지 결정만 하는 bottom sheet가 열린다.

## 8.3 Command Sheet

- 시간 sheet
- 유형 sheet
- 코치 sheet
- 메트로놈 sheet
- 기록 안내 sheet
- advanced sheet

한 sheet에 unrelated 설정을 섞지 않는다.

새 native bottom sheet dependency를 추가하지 않아도 React Native `Modal`, `Animated`, `Pressable`로 구현 가능하면 재사용한다.
기기 접근성·back·keyboard를 검증한다.

# 9. 화면별 상세 요구

## 9.1 오늘 화면

### 첫 viewport

1. greeting 또는 wordmark
2. 통합된 Today Action
3. 큰 start CTA
4. Run Rail 일부

Hero와 TodayCard를 합친다.

예:

```text
오늘은 25분 편하게
어제 조금 힘들었으니 속도보다 리듬에 집중해요.

[달리기 시작]
계획 회차 · 25분 · 러닝메이트 코치
```

### 그 아래

- 이번 주 compact strip
- 목표 대회 또는 가장 중요한 일정 1개
- 최근 완료 1개

### “더 보기”

아래 기능은 한 compact “둘러보기” module 또는 찾기로 이동:

- 대회 전체
- 러닝화
- 러닝 지식

### 합격

- typical user home은 2.5 화면 높이 안
- 첫 viewport primary CTA 1개
- 오늘 행동 설명 카드 1개
- 모든 기능 marketing 금지
- urgent 정보가 없을 때 빈 공간을 억지로 채우지 않음

## 9.2 훈련

상단 segmented:

```text
오늘 | 내 계획 | 라이브러리
```

### 오늘

- 오늘 추천 1개
- 대안 최대 2개
- 몸 상태로 가볍게 바꾸기
- 시작

### 내 계획

- 현재 plan만 먼저
- 이번 주 회차
- 다음 회차
- 일정
- plan 관리
- “새 계획 찾기”는 secondary

전체 40개 계획은 별도 catalog screen.

### 라이브러리

- 추천
- 편한 달리기
- 속도
- 긴 거리
- 러닝머신
- 회복
- 직접 만들기
- 검색

103개 카드를 세로로 쌓지 않는다.

### 도전·프로젝트·박자

- 박자 맞추기

## 9.3 달리기 setup

### 기본 노출

- 선택한 run
- 시간·거리·오픈엔드
- 코치 preset
- start

### 현재값 summary

- GPS 지원 여부
- 자동 멈춤
- 카운트다운
- 메트로놈

### 제거

기본 화면에서 제거:

- 모든 강도 설명
- 추천 대상 목록
- 피해야 할 날 목록
- 구조 전체
- 발화 밀도 숫자
- auto-pause 내부 시속표
- 몸무게 입력
- 개발 fallback 문구

이 정보는 `이 훈련 자세히`와 `고급 설정`에 둔다.

### active run

별도 `ActiveRunScreen`.

보이는 것:

- 경과 또는 남은 시간
- 현재 단계
- 다음 단계
- 거리·페이스가 실제로 있을 때
- pause
- finish
- 코치 빠른 조절
- 30초 조용히

숨길 것:

- global header
- bottom tabs
- 설정 목록
- 전체 cue history
- 모든 split 6개 기본 노출

split·route·log는 swipe 또는 상세 drawer.

### complete

- 핵심 결과
- 한 줄 회고
- 다음 행동
- 공유
- 저장 상태
