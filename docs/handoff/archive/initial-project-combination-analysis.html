3.1 — 내 이야기로 신발 찾기

해부학 용어를 먼저 고르는 방식에서 사용자의 일상적인 요청을 먼저 받는 방식으로 바꿨다. 발등이 높아서 눌려요 / 칼발이라 신발이 헐거워요 / 발목이 약하고 자주 흔들려요 / 족저근막염이 있어요가 시작 문구다. 자유 입력은 제한된 문구만 힌트로 읽으며 다음 화면에서 반드시 확인·수정한다. SurveyJS 기존 문답 엔진이 조건에 따른 질문과 필수 응답 검증을 처리한다. 답은 저장·전송하지 않는다. 용도·가격 후보와 발에 맞는지에 대한 검증은 구분하며, 상품 단위의 발등·칼발 근거가 부족한 상태를 표시한다.

3.1 — 문구·의학 안내·데이터 범위

Brooks·ASICS 공식 Shoe Finder의 용도→조건 확인 흐름을 참고했다. 해당 업체의 비공개 로직·상품 추천 데이터는 가져오지 않았다. NHS의 족저근막염 안내와 NHS 병원 신발 선택 자료를 연결했다. 발목이 약하다는 말에서 특정 보행 형태를 진단하지 않고 질환에 따른 상품 순위나 치료 보장을 만들지 않는다. 현재 통증 관련 답변은 기준 안내를 우선한다. 쿠션 등 공식 제품 특징이 확인된 후보는 일반 용도·예산 기준으로만 표시한다.

모델 발표일/모델 출시일/한국 판매일/신규 색상/재입고/수집 시각은 별도 필드다. Pegasus42 한국 2026-04-09처럼 근거가 있는 일자를 쓰고, AdiosPro4 글로벌 2025-01처럼 월까지만 확인된 경우 일자를 만들지 않는다. 확인된 미래 발표가 없으면 출시 예정은 빈 상태로 안내한다. 최신순은 출처와 지역이 붙은 모델 출시일 기준이며 한국 전체 시장 신제품 순위라고 표시하지 않는다.

v3 — 소통과 수익의 연결

NodeBB의 기존 소셜 보기·댓글·태그·대화를 우선 검토한다. 대회 상세→대회 이야기, 러닝화 상세→실제 착화 후기, 후기→같은 품번의 비교/공식 판매처로 연결한다. 사용자가 쓰는 글을 크루 기능과 분리한다. 광고/제휴 표시는 유지하고 광고비로 공식 상태·비교 사실·사용자 후기를 바꾸지 않는다. 익명 운영·오판 없는 완전 자동 관리는 약속하지 않으며 신고·차단·검토·스팸 제한은 기존 엔진 기능과 운영 규칙을 설정한다.

기존 재사용 기준 — 기존 기능 재사용 우선

사용자가 원하는 것은 이미 잘 운영되는 프로젝트의 기능을 하나의 깔끔한 앱에서 사용하는 것이다. 기존 엔진의 수집·검색·인증·알림·발행·분석 기능을 유지하고 공식 API·SDK·템플릿·설정으로 연결한다. 기능별로 한 담당 엔진을 정하며 동일 역할의 여러 제품을 동시에 붙이지 않는다. 인기도·문서상 기능·우리 환경에서의 실제 통합 검증은 구분한다.

이전 설계에서 바꾼 점

회원·관리자·콘텐츠 API는 Payload 공식 Website 템플릿을 우선 사용한다. 알림함과 예약/묶음 알림은 Novu 기존 컴포넌트와 워크플로로 연결한다. 광고 보고는 Umami 기존 캠페인·이벤트 분석을 사용하고 서비스 장애는 Uptime Kuma로 감시한다. 기존 단순 웹푸시 라이브러리의 역할은 필요 시 제공자 어댑터로 축소한다. 소통 피드·댓글·대화는 포함하며 크루 운영 기능은 제외한다.

코드를 최소화하는 통합 방식

각 프로젝트는 정식 패키지 또는 독립 서비스로 유지하고 버전·설정·출처를 기록한다. 우리 앱은 같은 사용자 ID와 대회 ID로 API 결과를 연결해 단일 화면과 알림함에 보여준다. 기존 제품의 관리자 화면은 운영자용으로 사용한다. 여러 앱의 로그인 화면을 사용자에게 나열하거나 전체 코드를 한 저장소에 섞는 방식은 택하지 않는다. 대회 연도·종목·접수 회차를 맞추는 데이터 설정과 연결 코드는 필요하다.

새로움이 생기는 지점

기존 도구의 조합으로 이용 흐름을 개선한다. 대회를 저장하면 해당 회차의 자격 체크리스트·접수 알림·개인 일정·준비물·관련 용품이 같은 페이지에 모인다. 추가접수와 정정 공지는 원래 저장한 대회 카드에 반영한다. 관심 러닝화는 내 조건과 가격 알림으로 이어지고 주간 브리핑은 내 지역·거리 조건으로 묶인다. 차별점은 새 알고리즘보다 정보의 연결·정확한 변경 반영·이용 단계의 연속성이다.

업그레이드 기능 묶음

① 내 조건으로 보는 접수 보드 ② 종목/회차별 신청 준비 체크리스트 ③ 대회 2~3개 공식 항목 비교 ④ 일정 변경 전후를 보는 이력 ⑤ 앱 내 통합 알림함과 알림 채널 선택 ⑥ 내 대회 준비 페이지와 예산 ⑦ 러닝화 모델/조건별 관심 가격 ⑧ 지역·종목별 접수 브리핑 ⑨ 광고·제휴 상품 표시와 실제 전환 보고 ⑩ 운영자 수집 실패·오래된 정보·정정 처리. 각 기능은 기존 제품의 담당 기능과 대회 데이터 설정을 연결해 만든다.

제품 방향

마라톤 대회 발견 → 접수 준비 → 신청 관련 일정 관리 → 대회 준비 → 장비 구매가 이어지는 개인 러너용 서비스. 초기 대상은 국내 5km·10km·하프·풀 마라톤이며 트레일·해외는 출처 연결을 추가하는 방식으로 확장한다. 크루는 이번 범위에서 제외한다.

화면 구성

오늘 / 대회 / 장비 / 소통 / 내 일정의 다섯 주요 화면. 오늘은 내 접수 일정·공식 변경·관심 장비 가격을 요약하고, 대회는 목록·지도·달력·비교, 장비는 모델·가격·알림, 내 일정은 관심·신청 예정·신청 완료·완주 상태와 준비물을 관리한다. 검색은 로그인 없이 제공하고 저장·알림에서 가입한다.

연결하고 설정할 최소 항목

대회-연도-종목-접수회차-자격의 공통 데이터 설정, 출처별 필드 근거, 공지 게시 시각·대회 연도·수집 시각 분리, 조기마감/추가접수 상태 매핑, 사용자 조건 필터, 일정 변경과 Novu 예약 변경 연결, 변경 이력, 상품 모델·색상·사이즈 식별, 기존 분석 보고와 제휴 정산 연결이 필요하다. 이 연결·설정과 화면 구성에 작업을 집중하고 기존 제품의 엔진을 재구현하지 않는다.

정보 수집과 운영

주최자 공식 API/등록 폼 → 공식 공지와 접수처 → 제휴 데이터 순으로 근거를 확보한다. 목록 사이트와 검색 결과는 발견용으로 쓰고 공식 근거로 확인한다. 허용된 공개 출처를 사이트별 요청 예산으로 수집한다. 접속 실패를 마감으로 처리하지 않고 미확인 표시와 관리자 경고를 만든다. 지난해 공지와 종목별 마감을 분리한다. 처음 보는 양식·충돌·취소 등 중요한 변경은 검토 대기열로 보낸다.

알림 설계

접수 발표/예정 시작/실제 열림 확인/마감 임박/조기마감/추가접수/기록 제출/환불 기한/배번호 수령/개최 변경을 별도 유형으로 저장한다. 사용자는 알림 시각·채널·방해 금지 시간을 고른다. 변경 시 이전 예약을 취소하고 새 버전으로 예약한다. 발송 작업은 중복 방지 키·재시도·만료·실패 대기열을 갖춘다. 웹 푸시와 이메일을 기본으로 하며 문자·카카오 비즈메시지는 계약·템플릿·발송 비용 확인 후 추가한다. 모든 사용자 기기의 도착 시각은 보장할 수 없으므로 서버 접수와 실제 수신 시험을 구분한다.

대회 비교와 참가 준비

공식 참가비·거리·지역·집결·제한시간·접수 방식·기념품·환불·교통 정보를 비교한다. 항목이 없으면 미발표로 표시한다. 대회 저장 시 캘린더·기록증·입금·준비물·배번호 수령 체크리스트를 연결한다. 개인 예산과 일정 충돌도 안내한다. 일정 파일 다운로드와 캘린더 구독을 구분하고 변경 동기화를 시험한다.

러닝화·용품

상품 모델과 버전을 기준으로 모으고 훈련용/레이스용·예산·공식 스펙·판매처·배송비·조건을 비교한다. 네이버 쇼핑 API는 검색과 가격 후보용이며 사이즈별 재고와 제휴 수수료를 보장하지 않는다. 재고·재입고는 판매처의 승인된 피드나 연동으로 확인한다. 관심 가격 알림·가격 확인 시각·색상과 사이즈 조건을 표시한다. 신발·양말·러닝벨트·보급식·모자 등을 본인 체크리스트와 연결하되 개인의 의료정보나 운동기록을 광고주에게 넘기지 않는다.

돈이 생기는 경로

① 가입·승인된 제휴 링크를 통한 확정 구매 수수료 ② 주간 접수 브리핑과 러닝용품 가이드의 협찬 ③ 주최자용 공식 등록·검증·모집 분석 패키지 ④ 개인 프리미엄 일정·고급 알림 ⑤ 정식 계약 대회의 접수 도구 이용료. 기본 검색·중요 변경은 무료로 제공한다. 제휴 링크·광고는 표시하고 광고비로 공식 접수 상태나 비교 기준을 바꾸지 않는다. 제휴 프로그램 가입이 모든 브랜드/상품 취급을 의미하지 않는다.

제휴 매출 가정

예시일 뿐 실제 실적·수수료가 아니다: 월 제휴 클릭 10,000 × 구매 전환 3% × 평균 주문 150,000원 × 확정 수수료 3% = 1,350,000원. 취소·반품·비인정 주문과 비용 차감 전 금액이다. 판매액 자체를 우리 매출로 기록하지 않고 확정 수수료만 매출로 본다. 초기에는 방문 수보다 알림 후 재방문·조건별 구독 유지·제휴 클릭·확정 전환·광고 재구매를 본다.

권장 기술 결합

운영 데이터와 회원 관리는 Payload 공식 템플릿을 우선 검토하며 현재 로컬 화면의 기존 모바일 런타임과 API로 연결할 계획이다. FullCalendar가 일정 화면, Meilisearch가 검색, Novu가 개인 알림과 알림함, listmonk가 구독 브리핑, n8n이 운영 파이프라인, Umami가 이용/전환 분석, Uptime Kuma가 서비스 감시를 담당한다. Crawlee·changedetection·Docling·RSSHub는 출처 유형에 맞는 작업자로 연결한다. 변경 이벤트를 보관한 뒤 동일 이벤트 ID로 Novu에 전달하고 실패 재처리 때 중복을 막는 연결을 검증한다. 사용자에게는 하나의 앱으로 보이게 구성한다.

기존 앱을 넘는 검수 기준

이것은 달성 목표이며 현재 검증 결과가 아니다. 대표 대회 50개·100개 종목/회차의 공식 대조 표본에서 핵심 날짜·자격 오기재 0건, 실패를 마감으로 오판 0건, 같은 변경 중복 알림 0건, 변경 후 낡은 예약 알림 0건을 목표로 한다. 예약 알림은 합의한 시험 환경에서 예정 시각±60초 이내 서버 발송 접수 99% 이상을 목표로 측정하며 단말 도착률은 별도로 기록한다. 변경 감지는 출처별 관측 주기 이내라는 기준을 적용한다. 실제 iOS/Android에서 권한·백그라운드·시간대·중복·정정 알림을 검증한다. 러닝화는 모델·색상·사이즈·배송 조건이 다른 가격을 같은 최저가로 섞지 않는다.

단계별 개발

1단계: 공식 정보 정본·수집기·일정·상세·비교·개인 저장·알림·관리자 검수. 2단계: 러닝화 카탈로그·가격 관심·제휴 전환·브리핑·광고 상품과 보고. 3단계: 주최자 직접 등록·수정·모집 분석과 계약 대회 접수. 각 단계는 이전 단계의 실데이터 검증을 통과한 뒤 공개 범위를 넓힌다. GPS 기록·개인 파일 가져오기는 유지율을 보고 선택 확장하며 크루는 포함하지 않는다.

비용을 확인하는 방법

소스가 무료여도 서버·DB·브라우저 수집·OCR·메일·문자·도메인·결제·검수·영업 비용이 든다. 1주일 수집 시험에서 페이지 수·변경률·OCR량·메일 수·평균 검토 시간을 측정해 월 비용을 산정한다. 접수 임박 출처와 정적인 안내문에 같은 감시 주기를 적용하지 않는다. 외부 API·제휴·국내 결제 조건은 실제 계정과 계약 확인 전 확정하지 않는다.

REA 활용 범위

reverse-engineer-anything 스킬을 확인했다. 공개 소스 저장소의 구조·기능 검토는 일반 소스 도구로 수행하며, 현재는 분석할 배포 바이너리·네트워크 캡처가 없어 REA 분석 도구는 실행하지 않았다. 향후 선택한 배포 패키지의 구조나 실제 앱 연동 오류가 소스만으로 설명되지 않을 때 REA를 사용하고 관측·추정·미확인을 구분한다. REA는 대회 데이터 공급원이나 기능 사용권을 제공하지 않는다.

검증 상태

이번 결과는 공개 문서·저장소 메타데이터·선택한 README 근거를 바탕으로 한 도입 설계 v3다. 백엔드 서비스 통합·전체 소스 감사·실제 알림 발송·공식 제휴·상용 결제·완성 앱 검증은 수행하지 않았다. 기존 프로젝트에 사용 사례가 있다는 사실이 우리 통합본의 검증 완료를 의미하지 않는다. 인기 순위와 제품 적합성을 분리했다. 100% 우월성은 선언하지 않고 위 표본 비교와 실제 사용자 시험으로 확인한다.
