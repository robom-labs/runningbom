## 0. 목표와 진실성

러닝봄이 100만 다운로드나 100억 원 가치에 도달한다고 보장할 수는 없다. 다운로드는 코드뿐 아니라 유지율, 유통, 브랜드, 제휴, 자본과 타이밍이 함께 결정한다.

이번 작업은 성공 가능성을 높이기 위해 다음 순서를 강제한다.

1. 틀린 기록과 저장 손실을 먼저 막는다.
2. 첫 실행에서 첫 운동까지 걸리는 시간을 줄인다.
3. 대회 발견 → 목표 지정 → 훈련 계획 → 오늘 운동 → 기록 → 공유를 한 흐름으로 잇는다.
4. 관찰하지 않은 수치와 존재하지 않는 커뮤니티를 꾸며내지 않는다.
5. 현재 Play 심사 계약을 깨는 새 권한과 서버 기능은 섞지 않는다.
6. 유지율이 증명되기 전에 광고로 운동 경험을 훼손하지 않는다.

## 이번 감사에서 바로잡은 것

- 제품 설명은 과거 “대회 접수 알림 앱”에 머물렀지만 실제 앱은 종합 러닝 코치다.
- 러닝화 데이터는 두 층이다. `shoeCatalog`는 100종 초과의 탐색 정본이고, 원격/legacy 공식 확인 묶음은 8건이다. 둘을 전체 수량으로 혼동하지 않는다.
- 첫 실행은 실제 로그인 제공 여부와 관계없이 로그인 준비 화면을 필수 통과했다.
- 9주 프로그램 완료가 홈·주간 목표·연속 기록·배지 공통 활동으로 이어지지 않았다.
- 대회를 목표로 정한 뒤 훈련 계획으로 이동하는 다음 행동이 약했다.
- 원격 대회 링크와 정적 데이터 원본 주소의 신뢰 범위를 더 좁힐 필요가 있었다.

# 2. 제품 북극성

> **한국 초보 러너가 국내 목표 대회를 발견하고, 오늘 해야 할 한 번의 운동을 이해한 뒤, 한국어 코치와 안전하게 끝내도록 돕는 앱.**

사용자가 앱을 열고 10초 안에 답을 얻어야 하는 질문은 다섯 개다.

1. 오늘 뛰어야 하나, 쉬어야 하나?
2. 뛴다면 무엇을 얼마나 해야 하나?
3. 목표 대회까지 제대로 가고 있나?
4. 끝낸 운동이 목표와 성취에 반영됐나?
5. 다음에는 언제 무엇을 하면 되나?

피해야 할 제품은 다음과 같다.

- 기능은 많지만 오늘 할 일이 보이지 않는 러닝 백화점
- 검증 안 된 대회·신발·건강 정보를 많이 쌓은 검색 앱
- 광고 노출을 위해 화면과 클릭을 늘린 앱
- 실제 사용자가 없는데 커뮤니티가 활발한 척하는 앱
- Production에서 제공하지 않는 GPS를 제공하는 것처럼 홍보하는 앱

# 3. 경쟁 제품에서 채택할 원리

## Nike Run Club

공식 제품 설명은 음성 안내 러닝, 목표별 계획, 기록·구간·신발 거리, 도전과제·성취, 기록 공유를 하나의 러닝 흐름으로 연결한다.

- 채택: 코치가 숫자만 읽지 않고 운동 목적과 몸의 감각을 설명
- 변형: 쉬운 한국어와 국내 목표 대회 중심
- 거절: 워치·심박·라이브 위치처럼 현재 없는 데이터를 있는 것처럼 표시

- 거절: 현재 입력과 기록보다 정교해 보이는 가짜 개인화

참고: `https://www.adidas.com/us/running-app`

# 4. 지금 없어서 치명적인 것 — 7개

## 1. 최소 동의형 제품 측정

- **무엇**: 동의한 사용자에 한해 온보딩 완료, 첫 운동 시작·완료, 두 번째 운동, 목표 대회 저장, 계획 보기, 공유 성공을 익명 집계.
- **왜**: 설치 수만으로는 이탈 화면을 알 수 없다.
- **코드**: `services/analytics`와 의미 있는 성공 이벤트만. 위치 원본·광고 ID 수집 금지.
- **난이도**: 1주 이상
- **서버**: 필요
- **새 권한**: 불필요
- **위험**: 동의·보존·삭제 정책이 부실하면 신뢰 손상.

## 2. “오늘 상태가 안 좋아요” 계획 조절

- **무엇**: `괜찮아요 / 피곤해요 / 뻐근해요 / 아파요` 선택. 피곤하면 시간 축소, 뻐근하면 쉬운 걷기·회복, 통증이면 휴식과 전문 진료 안내.
- **왜**: 계획은 지키게 하는 기능만큼 흐트러졌을 때 다시 잇는 기능이 중요하다.
- **코드**: `domains/programs`, `ProgramsScreen`, `StartScreen`, 완료 피드백.
- **난이도**: 1주
- **서버**: 불필요
- **새 권한**: 불필요
- **위험**: 의료 진단처럼 표현 금지.

## 3. 놓친 주간 계획 재정렬

- **무엇**: 3회 이상 또는 한 주를 놓치면 `그대로 계속 / 쉽게 다시 시작 / 목표일까지 다시 맞춤` 제공.
- **왜**: 한 번 밀린 사용자가 앱까지 포기하는 것을 막는다.
- **코드**: `domains/programs/racePlan.ts`, 홈의 다음 행동, 계획 버전 저장.
- **난이도**: 1주 이상
- **서버**: 불필요
- **새 권한**: 불필요
- **위험**: 덮어쓰기 전 이전 버전과 되돌리기 필수.

## 4. 기기 변경·삭제에 견디는 복원

- **무엇**: 먼저 파일 내보내기·가져오기, 이후 로그인 기반 암호화 복원.
- **왜**: 몇 달 기록이 휴대폰 교체로 사라지면 신뢰가 끝난다.
- **코드**: `services/storage`, `domains/identity`, 설정의 백업·복원.
- **난이도**: 파일 1주, 계정 동기화 그 이상
- **서버**: 파일은 불필요, 계정 동기화는 필요
- **새 권한**: 시스템 문서 선택기를 쓰면 불필요
- **위험**: 충돌 병합·삭제·이식성·암호화.

## 5. 실제 이미지 기록 공유

- **무엇**: 완료 화면에서 디자인 3개, 표시할 기록 선택, 위치 기본 제외, 공식 설치 주소 포함.
- **왜**: 카카오톡·인스타그램에서 텍스트보다 다시 보이고 설명 없이 전달된다.
- **코드**: `domains/social`, 공유 카드 화면, 랜딩 페이지.
- **난이도**: 3일~1주
- **서버**: 불필요
- **새 권한**: 시스템 공유만 쓰면 불필요
- **위험**: 경로·위치의 기본 노출 금지.

## 6. Production GPS 출시 결정

- **무엇**: Preview에서 도심·강변·신호등·건물 밀집·화면 잠금·전화·배터리 절약을 검증한 뒤 별도 릴리스에서 권한 추가 여부 결정.
- **왜**: GPS는 중요하지만 틀린 거리와 중간 기록 손실은 기능 부재보다 나쁘다.
- **코드**: `domains/tracking`, `StartScreen`, `app.config.js`, 개인정보 고지.
- **난이도**: 1주 이상 + 스토어 심사
- **서버**: 불필요
- **새 권한**: 추후 앱 사용 중 위치
- **위험**: 현재 비공개 테스트 심사 흐름 재시작 가능성.

## 7. 서명된 정적 데이터 배포

- **무엇**: 현재 SHA-256 manifest에 운영 서명을 붙이고 앱 내 공개키로 검증. 실패하면 마지막 정상본 유지.
- **왜**: checksum만 있는 manifest는 배포 계정 탈취 시 manifest와 데이터가 함께 바뀔 수 있다.
- **코드**: 데이터 생성 스크립트, `services/static-data`, GitHub Actions 비밀 서명키.
- **난이도**: 1주
- **서버**: 불필요
- **새 권한**: 불필요
- **위험**: 키 회전·복구 절차 없이 도입하면 정상 업데이트까지 막을 수 있음.

# 5. 러닝봄이 넘어설 수 있는 지점 — 5개

1. **국내 대회에서 오늘 운동까지 한 번에**: 대회 발견, 접수 알림, 목표 지정, 남은 기간 계획, 오늘 운동을 한 흐름으로 연결.
2. **초보자용 쉬운 한국어 코치**: `숨이 차지만 짧게 말할 수 있는 속도`, `오늘은 빨리보다 편하게`처럼 행동을 바로 이해.
3. **못 지킨 사람을 다시 데려오는 코치**: 업무·여행·피로·가벼운 불편으로 흐트러진 사용자의 안전한 복귀를 제품 중심에 둠.
4. **많아 보이기보다 출처가 보이는 데이터**: 대회·신발·건강 안내에 출처·검증일·비어 있는 값의 이유를 제공.
5. **운동 완료가 광고보다 먼저**: 운동 중·저장 직전·중요 알림 직전 광고 금지. 추가 효용에만 유료 가치 부여.

# 6. 사람이 사람을 데려오는 성장 장치 — 5개

1. **기록 공유 → 공식 설치 랜딩**: 현재 PR에서 텍스트 공유 주소를 연결. 다음은 위치 제외 이미지 카드와 안전한 설치 링크.
2. **같은 목표 대회 준비**: 공유받은 사용자가 같은 대회를 목표로 저장하고 준비 계획으로 바로 이동.
3. **친구 3명 주간 약속**: 개인 위치·경로 없이 각자 목표 완료만 합산. 서버·초대 스팸·부정 기록 방어 필요.
4. **회사·동호회 챌린지**: 개인 위치를 숨기고 참여율·완료 수만 제공하는 B2B 복지 상품.
5. **대회 주최사 공식 준비 코스**: 접수 페이지에서 러닝봄 계획·준비물·공지로 연결하는 제휴.

- 목표 대회 화면에서 훈련 계획으로 바로 이동.
- 9주 프로그램 완료를 홈·주간 목표·연속 기록·배지 공통 활동에 연결.
- 5분 미만 오작동, 회차 ID 불일치, 잘못된 완료 시각, 과도한 경과값, 중복 완료 방어.

## 성장

- 실제 내 기록 공유 글에 누구나 열 수 있는 공식 러닝봄 랜딩 주소를 한 번만 포함.
- 존재하지 않는 사용자·좋아요·댓글을 만들지 않는 원칙 유지.

## 보안·신뢰

- 대회 데이터 주소를 로봄 관리 경로로 제한.
- HTTP, 자격정보 포함 URL, localhost·사설망·제어문자 주소 거부.
- 기존 대회 공식 링크 도메인 교체와 새 대회의 미검증 도메인 차단.
- 정적 데이터 원본을 GitHub Pages 또는 `static.robom.kr/runningbom` 경로로 제한.
- 기존 SHA-256·크기·건수 검증과 마지막 정상본 복구 유지.

## 제품 정체성·운영

- 루트 README, 모바일 README, 앱 설명을 실제 종합 러닝 코치에 맞게 수정.

- 일시정지와 종료는 색뿐 아니라 글자·형태로 구분.
- 잠금·전화·오디오 포커스 뒤에도 기록과 코치가 일관되게 복구.

## 접근성

- 200% 글자 확대, 읽기 순서, 접근 가능한 버튼 이름, 색 이외 상태 표현.

- 작은 Android 화면, 태블릿·가로 회전에서 잘림·가로 넘침 금지.

# 11. 100억 목표를 위한 수익 구조

광고만으로 100억 원 개인 자산을 만드는 것은 반복 사용이 매우 큰 경우가 아니면 어렵다. 러닝봄은 운동 중 광고를 늘리는 대신 반복 매출과 제휴 가치를 만들어야 한다.

## 무료 핵심

오늘 운동, 기본 코치, 로컬 기록, 국내 대회 탐색과 기본 알림은 무료로 유지한다.

## 프리미엄 후보

- 고급 목표 대회 계획과 계획 재정렬
- 기기간 복원·상세 비교·장기 추세
- 추가 코치 프로그램과 계획 버전 보관
- 광고 제거가 아니라 실제 추가 효용을 판매

## B2B·제휴 후보

- 대회 주최사 공식 준비 코스와 참가자 안내
- 회사·동호회 건강 챌린지
- 검증된 러닝화 제휴와 수수료 고지
- 러닝 매장·코치와 지역 프로그램 연결

유료 사용자 10만 명이 월 4,900원을 결제하면 월 총결제액은 4억 9천만 원이지만, 스토어 수수료·세금·환불·서버·인력·마케팅을 빼야 하고 10만 유료 사용자에 도달한다는 보장도 없다. 먼저 반복해서 쓰는 무료 제품을 증명하고 그 위에 결제 이유를 쌓는다.

# 12. 우선순위 1~10

1. PR #39 자동검사와 코드 리뷰를 전부 통과.
2. Android 실기기에서 첫 실행 → 첫 운동 → 저장 → 재실행 검증.
3. 일시정지·잠금·전화·음악·이어폰 회귀 검증.
4. 최소 동의형 제품 지표와 개인정보 문서 정합.
5. 운동 전 상태 확인과 안전한 계획 조절.
6. 놓친 주간 재정렬과 계획 되돌리기.
7. 위치 제외 이미지 공유와 같은 대회 링크.
8. 파일 백업·복원 후 계정 복원.
9. 정적 manifest 서명과 키 회전·복구.

개발 순서는 **기록 신뢰 → 첫 운동 완료 → 두 번째 운동 → 안전한 복귀 → 자연 공유**다. 이 다섯 단계가 작동하지 않으면 광고·커뮤니티·데이터 수량을 늘려도 사람이 남지 않는다.
