## 0. 먼저 분명히 할 것

러닝봄이 100만 다운로드나 100억 원 가치에 도달한다고 보장할 수는 없다. 다운로드는 코드 품질만으로 결정되지 않고 유통, 브랜드, 유지율, 자본, 제휴와 타이밍이 함께 결정한다.

대신 이번 계획은 다음을 목표로 한다.

1. 기록을 틀리게 만들 수 있는 오류를 먼저 없앤다.
2. 사용자가 첫 실행 뒤 가능한 한 빨리 첫 운동을 시작하고 끝내게 한다.
3. 대회 탐색, 훈련 계획, 실제 운동, 기록, 성취 공유가 한 흐름으로 이어지게 한다.
4. 관찰되지 않은 성공 숫자나 존재하지 않는 커뮤니티를 꾸며내지 않는다.
5. 정식 앱의 현재 Play 심사 계약을 깨는 새 권한과 서버 의존 기능을 섞지 않는다.
6. 성장을 측정할 준비가 되기 전 광고로 사용 경험을 훼손하지 않는다.

| 영역 | 이유 |

| 실시간 커뮤니티·회사 챌린지 | 서버와 운영·신고·차단·개인정보 체계가 필요 |
| 이미지 공유 카드 | 현재는 정직한 텍스트 공유가 우선. 네이티브 이미지 생성·공유 모듈은 별도 검증 필요 |
| 스토어 출시 완료 | Play Console, 서명, 실제 심사·배포 상태는 저장소만으로 확정할 수 없음 |
| 100만 다운로드 가능성 | 실제 설치·유지·공유·스토어 전환 데이터가 아직 없음 |

## 1.3 이번 감사에서 바로 잡은 오래된 주장

- 루트 설명은 앱을 아직 “대회 접수 알림 앱”이라고 소개하고 있었지만 실제 코드는 종합 러닝 코치다.
- 과거 기획문에는 러닝화 135종이라고 적혀 있으나 현재 검증 정본은 8종이다.
- 첫 실행은 실제 로그인이 제공되지 않아도 로그인 준비 화면을 필수로 통과했다.
- 9주 프로그램 완료는 프로그램 진도에는 남지만 홈·주간 목표·연속 기록·배지의 공통 활동에는 연결되지 않았다.
- 대회를 목표로 정한 뒤 훈련 계획으로 이어지는 다음 행동이 약했다.
- 원격 대회 공식 링크와 정적 데이터 원본 주소의 신뢰 범위를 더 좁힐 필요가 있었다.

# 2. 제품 북극성

## 한 문장

> **한국 초보 러너가 국내 목표 대회를 발견하고, 오늘 해야 할 한 번의 운동을 이해한 뒤, 한국어 코치와 안전하게 끝내도록 돕는 앱.**

## 러닝봄이 이겨야 하는 순간

사용자가 앱을 열고 10초 안에 다음 질문에 답을 얻어야 한다.

1. 오늘 뛰어야 하나, 쉬어야 하나?
2. 뛴다면 무엇을 얼마나 해야 하나?
3. 목표 대회까지 제대로 가고 있나?
4. 끝낸 운동이 내 목표와 성취에 반영됐나?
5. 다음에는 언제 무엇을 하면 되나?

## 피해야 하는 정체성

- 기능이 많지만 오늘 할 일이 보이지 않는 러닝 백화점
- 검증되지 않은 신발·대회·건강 정보를 많이 쌓은 검색 앱
- 광고를 보게 하기 위해 화면을 늘린 앱
- 실제 사용자가 없는데 커뮤니티가 활발한 척하는 앱
- GPS를 제공하지 않는 Production에서 GPS 앱처럼 홍보하는 앱

# 4. 지금 없어서 치명적인 것 — 우선 7개

## 1. 실제 유지율을 알 수 있는 최소 측정

- **무엇**: 사용자가 동의한 경우에만 온보딩 완료, 첫 운동 시작·완료, 두 번째 운동, 계획 보기, 대회 목표 저장, 공유 성공을 익명 집계한다.
- **왜**: 설치 수만 보면 어느 화면에서 이탈하는지 알 수 없다. 측정 없이 디자인을 바꾸면 취향 싸움이 된다.
- **우리 코드 어디**: `services/analytics`, 각 화면의 의미 있는 성공 이벤트. 광고 ID와 위치 원본은 수집하지 않음.
- **난이도**: 1주 이상
- **서버 필요**: 필요. 무료 구간이 있는 분석 도구 또는 자체 Supabase 집계.
- **새 권한 필요**: 불필요
- **위험**: 동의·보존·삭제 정책이 부실하면 신뢰를 잃음.

## 2. “오늘 상태가 안 좋아요” 계획 조절

- **무엇**: 프로그램·계획 시작 전 `괜찮아요 / 피곤해요 / 뻐근해요 / 아파요` 중 하나를 고른다. 피곤하면 시간을 줄이고, 뻐근하면 쉬운 걷기·회복으로 바꾸며, 통증은 운동 대신 쉬기와 전문 진료 안내를 보여 준다.
- **왜**: 계획은 지키는 기능만큼 망가졌을 때 안전하게 돌아오는 기능이 중요하다.
- **근거**: Runna의 “Not Feeling 100%”와 계획 재정렬.
- **우리 코드 어디**: `domains/programs`, `ProgramsScreen`, `StartScreen`, 활동 완료 피드백.
- **난이도**: 1주
- **서버 필요**: 불필요
- **새 권한 필요**: 불필요
- **위험**: 의료 진단처럼 보이면 안 됨. 응급·지속 통증은 전문가 안내.

## 3. 놓친 주간을 다시 잇는 계획 재정렬

- **무엇**: 3회 이상 또는 한 주를 놓치면 `그대로 계속 / 이번 주 쉽게 다시 시작 / 목표일까지 계획 다시 맞춤`을 보여 준다.
- **왜**: 사용자가 계획에서 한 번 밀리면 앱 자체를 포기하기 쉽다.
- **우리 코드 어디**: `domains/programs/racePlan.ts`, 프로그램 진행 저장, 홈의 다음 행동.
- **난이도**: 1주 이상
- **서버 필요**: 불필요
- **새 권한 필요**: 불필요
- **위험**: 기존 계획을 덮어쓰기 전 이전 버전과 되돌리기 제공 필요.

## 4. 기기 변경·삭제에 견디는 복원

- **무엇**: 로그인한 사용자는 활동·목표·관심 대회·신발·설정을 암호화된 계정 데이터로 복원한다. 로그인하지 않은 사용자는 파일 내보내기·가져오기를 제공한다.
- **왜**: 몇 달 기록한 사용자가 휴대폰 교체로 전부 잃으면 신뢰가 끝난다.
- **우리 코드 어디**: `services/storage`, `domains/identity`, Supabase migration·RLS, 설정의 내보내기·복원.
- **난이도**: 그 이상
- **서버 필요**: 계정 동기화에는 필요. 파일 백업은 불필요.
- **새 권한 필요**: 시스템 문서 선택기를 쓰면 별도 저장소 권한 불필요.
- **위험**: 충돌 병합, 계정 삭제, 데이터 이식성과 암호화가 필수.

## 5. 실제 이미지 기록 공유

- **무엇**: 운동 완료 화면에서 세 가지 디자인을 미리 보고, 거리·시간·1km당 시간·배지·목표 대회만 골라 이미지로 공유한다. 공유물에는 짧은 공식 설치 주소가 들어간다.
- **왜**: 텍스트보다 이미지가 카카오톡·인스타그램에서 다시 보이고 설명 없이 전달된다.
- **우리 코드 어디**: `domains/social`, 공유 카드 화면, 랜딩 페이지.
- **난이도**: 3일~1주
- **서버 필요**: 불필요
- **새 권한 필요**: 시스템 공유만 쓰면 불필요
- **위험**: 경로 지도·위치가 기본 포함되면 개인정보 노출. 기본은 위치 제외.

## 6. Production GPS의 정직한 출시 결정

- **무엇**: Preview 실기기에서 도심·강변·건물 밀집·신호등·화면 잠금·전화 수신·배터리 절약을 검증한 뒤, 별도 릴리스에서 위치 권한을 추가할지 결정한다.
- **왜**: 종합 러닝 앱에서 거리·페이스는 중요하지만, 현재 심사 중인 앱에 서둘러 권한을 넣으면 출시와 신뢰를 동시에 잃을 수 있다.
- **우리 코드 어디**: `domains/tracking`, `StartScreen`, `app.config.js`, 개인정보 고지.
- **난이도**: 1주 이상 + 스토어 심사
- **서버 필요**: 불필요
- **새 권한 필요**: 추후 앱 사용 중 위치 권한
- **위험**: 오차가 큰 GPS는 기능이 없는 것보다 나쁨.

## 7. 공개 데이터의 서명된 배포

- **무엇**: 현재 SHA-256 manifest에 운영 서명을 추가하고 앱 안의 공개키로 서명을 검증한다. 서명이 없거나 틀리면 마지막 정상본을 유지한다.
- **왜**: checksum만 있는 manifest는 배포 계정이 탈취되면 공격자가 manifest와 데이터 모두 바꿀 수 있다.
- **우리 코드 어디**: 정적 데이터 생성 스크립트, `services/static-data`, GitHub Actions 비밀 서명키.
- **난이도**: 1주
- **서버 필요**: 불필요. 배포 파이프라인 필요.
- **새 권한 필요**: 불필요
- **위험**: 키 회전·복구 절차 없이 도입하면 정상 업데이트도 막힐 수 있음.

# 5. 모방을 넘어설 수 있는 지점 — 5개

## 1. 국내 대회 → 오늘 훈련까지 한 번에

해외 앱은 세계 공통 계획이 강하지만 국내 대회 접수 시각·공식 링크·지역 맥락은 약하다. 러닝봄은 대회 발견, 접수 알림, 목표 지정, 남은 기간 계획, 오늘의 운동까지 하나의 흐름으로 묶을 수 있다.

## 2. 초보자를 위한 쉬운 한국어 코치

복잡한 훈련 용어를 설명하는 대신 `숨이 차지만 짧게 말할 수 있는 속도`, `오늘은 빨리보다 편하게`처럼 행동을 바로 이해하게 한다. 한국어 표현의 자연스러움은 단순 번역으로 따라오기 어렵다.

## 3. 못 지킨 사람을 다시 데려오는 코치

완벽한 일정 수행보다 피곤함·업무·여행·가벼운 통증으로 흐트러진 사용자가 안전하게 복귀하는 흐름을 제품 중심에 둔다.

## 4. 데이터가 적어도 출처가 보이는 앱

대회·신발·건강 안내는 수량보다 출처·검증일·확실하지 않은 필드의 빈칸이 중요하다. `많아 보이기 위해 추측값 채우기`를 하지 않는 것이 장기 신뢰의 차별점이다.

## 5. 광고보다 운동 완료가 먼저인 수익화

운동 중, 알림 직전, 기록 저장 직전에는 광고를 넣지 않는다. 무료 핵심 경험을 지킨 뒤 고급 계획·복원·상세 분석·파트너 혜택을 분리한다.

# 6. 사람이 사람을 데려오는 성장 장치 — 5개

## 1. 기록 공유 → 설치 랜딩

- 현재 PR: 텍스트 공유에 공식 랜딩 주소를 한 번 포함.
- 다음 단계: 위치를 기본 제외한 이미지 카드, 설치 후 같은 대회·도전을 바로 여는 안전한 링크.
- 성공 조건: 공유한 사람의 기록이 광고처럼 보이지 않고, 받은 사람이 앱의 가치를 즉시 이해.

## 2. 목표 대회 함께 준비

- 한 사람이 대회를 공유하면 받은 사람은 앱 설치 후 같은 대회를 목표로 저장한다.
- 서버 전: 링크 공유와 로컬 준비 체크.
- 서버 후: 대회별 소규모 그룹, 공지·신고·차단·탈퇴 포함.

## 3. 친구 3명 주간 약속

- `이번 주 각자 2번 달리기`처럼 개인 기록의 합계만 공유한다.
- 순위보다 모두 완료를 우선한다.
- 서버가 필요하며 부정 기록·초대 스팸·청소년 보호를 함께 설계한다.

## 4. 회사·동호회 챌린지

- 관리자가 링크를 만들고 구성원은 최소 정보로 참여한다.
- B2B 복지비·행사비로 결제할 수 있는 별도 상품 후보.
- 관리자 통계는 개인 위치·경로를 노출하지 않고 참여율·완료 수만 제공.

## 5. 대회 주최사 공식 준비 코스

- 대회 주최사가 접수 페이지에서 러닝봄 준비 링크를 제공한다.
- 러닝봄은 공식 일정·준비물·연습 계획·공지 확인을 묶는다.
- 광고 배너보다 사용자 의도와 맞고, 주최사는 문의 감소와 참가자 완주율 개선을 기대할 수 있다.

# 10. 측정할 숫자

현재 실제 사용자 지표가 없으므로 아래 값은 성과가 아니라 **출시 가설과 게이트**다. 관찰 데이터가 생기면 다시 정한다.

| 지표 | 초기 가설 | 의미 |
|---|---:|---|
| 온보딩 완료율 | 75% 이상 | 첫 실행이 너무 길거나 부담스럽지 않은지 |
| 설치 후 24시간 내 첫 운동 시작 | 35% 이상 | 앱의 가치가 행동으로 이어지는지 |
| 시작한 운동 완료율 | 70% 이상 | 코치·화면·저장 흐름이 견딜 만한지 |
| 첫 운동 후 7일 안 두 번째 운동 | 30% 이상 | 일회성 체험을 넘는지 |
| D7 유지율 | 20% 이상 | 주간 습관이 생기는지 |
| D30 유지율 | 10% 이상 | 계획과 목표 대회가 장기 가치를 만드는지 |
| 기록 공유율 | 완료 운동의 5% 이상 | 자연 유입 고리가 생기는지 |
| 충돌 없는 실행 | 99.8% 이상 | 성장 전에 신뢰를 지키는지 |
| 기록 저장 실패 | 0.1% 미만 | 운동 앱의 핵심 신뢰 |

어떤 수치도 실제 관찰 전에 달성했다고 보고하지 않는다.

# 11. 100억 목표를 위한 수익 구조

광고 노출만으로 100억 원 개인 자산을 만드는 것은 사용자 수와 반복 사용이 매우 큰 경우가 아니면 어렵다. 러닝봄은 운동 중 광고를 늘리는 대신 반복 매출과 제휴 가치를 만들어야 한다.

## 무료 핵심

- 오늘 운동, 기본 코치, 로컬 기록, 국내 대회 탐색과 기본 알림.
- 설치 후 가치를 확인하기 전 결제를 요구하지 않음.

## 프리미엄 후보

- 고급 목표 대회 계획과 계획 재정렬.
- 기기간 복원·상세 비교·장기 추세.
- 추가 코치 프로그램과 계획 버전 보관.
- 광고 제거가 아니라 실제 추가 효용을 판매.

## B2B·제휴 후보

- 대회 주최사 공식 준비 코스와 참가자 안내.
- 회사·동호회 건강 챌린지.
- 검증된 러닝화 제휴와 명확한 수수료 고지.
- 러닝 매장·코치와 지역 프로그램 연결.

예시 계산은 사업 가설일 뿐이다. 유료 사용자 10만 명이 월 4,900원을 결제하면 월 총결제액은 4억 9천만 원이지만, 스토어 수수료·세금·환불·서버·인력·마케팅을 빼야 하며 그 사용자 수에 도달한다는 보장은 없다. 목표는 먼저 `반복해서 쓰는 무료 제품`을 증명하고 그 위에 결제 이유를 쌓는 것이다.
