# 성능 점검 결과

## 점검 범위

현재 코드의 요청 횟수, 목록 상한, 로컬 데이터베이스 설정, 반복 타이머 사용을 정적으로 확인했다. 프로파일러, 실제 기기 프레임 속도, 시작 시간, 메모리, 배터리, 네트워크 사용량은 측정하지 않았다.

## 코드에서 확인한 성능 방어

- 대회 원격 데이터는 `RaceStateProvider`에서 한 번 요청하며 `AbortController`로 중단할 수 있다.
- 원격 revision이 현재 revision과 같으면 상태 교체를 생략한다.
- 공개 피드는 요청 수를 1~50 범위로 제한한다.
- 홈은 다가오는 대회와 커뮤니티 하이라이트를 제한된 개수만 표시한다.
- 대회 번들 데이터는 183건이며 오프라인 fallback으로 사용한다.
- SQLite는 WAL 모드를 사용하고 활동 완료 시각 인덱스가 있다.
- 정적 데이터는 checksum과 크기를 포함한 manifest로 생성 시점 무결성을 검사한다.
- 네이티브 코치가 활성화된 동안 화면은 1초 간격으로 런타임 상태를 조회한다. 코칭 cue 시간 계산 자체는 Kotlin 서비스에서 수행한다.

## 측정 결과

현재 문서 작업에서는 성능 수치를 측정하지 않았다.

| 항목 | 상태 |
| --- | --- |
| Android cold start | `NOT_RUN` |
| Android warm start | `NOT_RUN` |
| Android Hermes bundle 크기 | `4,182,720 bytes` |
| iOS Hermes bundle 크기 | `4,175,295 bytes` |
| Preview APK 크기 | `92,194,976 bytes` |
| production AAB 크기 | `61,834,966 bytes` |
| 홈·탐색 스크롤 FPS | `BLOCKED_EXTERNAL` |
| 183개 대회 검색 응답 시간 | `NOT_RUN` |
| SQLite 읽기·쓰기 시간 | `NOT_RUN` |
| 60분 코칭 배터리 사용량 | `BLOCKED_EXTERNAL` |
| 네트워크 요청 횟수 | `NOT_RUN` |
| 메모리 누수 | `NOT_RUN` |

기존 기준선 문서에는 과거 AAB 크기가 약 47MiB로 기록돼 있다. 현재 AAB는 61,834,966 bytes이므로 단순 파일 크기는 증가했다. 기능 범위와 native module이 달라 직접 동등 비교는 아니며, 실기기 설치 크기·시작 성능은 별도로 측정해야 한다.

## 확인이 필요한 위험

- 시작 화면의 1초 상태 조회가 긴 세션에서 JS wake-up과 배터리에 미치는 영향을 측정해야 한다.
- 대회와 러닝화 화면이 `ScrollView`를 사용하므로 데이터 증가 시 가상화 전환 필요 여부를 측정해야 한다.
- 커뮤니티 공개 피드는 최대 50건이지만 현재 페이지네이션 UI가 없다.
- 홈의 가로 러닝화 목록과 배지 목록은 저사양 기기에서 실제 렌더 비용을 확인해야 한다.
- 기기 TTS와 foreground service가 제조사별 절전 정책에서 유지되는지 성능·신뢰성을 함께 검증해야 한다.

## 현재 판정

명확한 요청 반복 방지와 목록 상한은 코드에서 확인했고 Android·iOS production export bundle 크기를 기록했다. 시작 시간, FPS, 메모리, 배터리와 실기기 네트워크 횟수는 측정하지 않았으므로 성능 전체를 PASS로 판정하지 않는다.
