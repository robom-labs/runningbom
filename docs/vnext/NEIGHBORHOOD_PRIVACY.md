# 동네 기능 개인정보 현황

## 현재 구현

현재 앱은 사용자가 `마이 → 내 동네` 입력란에 직접 적은 문자열만 기기 설정에 저장한다.

- 표시 문자열은 `neighborhoodLabel`에 저장된다.
- 식별 문자열은 `selected:<사용자 입력>` 형식의 `neighborhoodCode`로 저장된다.
- 저장 위치는 AsyncStorage의 `runningbom:vnext:preferences:v1`이다.
- 위치 권한 요청, GPS 좌표 수집, 경계 파일 다운로드, point-in-polygon 판정은 구현돼 있지 않다.
- 서버로 원시 좌표를 보내거나 데이터베이스·로그에 좌표를 저장하는 코드도 없다.

현재 UI의 값은 사용자가 직접 고른 동네이며 위치 인증이나 실거주 인증이 아니다.

## 기능 플래그

`EXPO_PUBLIC_NEIGHBORHOOD_DEVICE_CONFIRMATION_ENABLED`가 참일 때만 기기 위치 확인 기능을 열도록 플래그가 정의돼 있다. 기본값은 꺼짐이다.

플래그가 있어도 현재 저장소에는 다음 구현이 없다.

- 위치 권한 요청
- 공식 행정구역 경계 데이터
- 경계 데이터 라이선스·출처 표시
- 기기 내 좌표 판정
- 정확도·모의 위치 신호 처리
- 만료·재확인 처리

따라서 플래그를 켜는 것만으로 기능이 완성되지 않는다.

## 서버 스키마

`neighborhood_status`는 다음 상태를 표현할 수 있다.

- `DEVICE_LOCATION_CONFIRMED`
- `USER_SELECTED`
- `EXPIRED`
- `RISK_REVIEW`

그러나 현재 일반 클라이언트 RLS는 본인 행이면서 상태가 `USER_SELECTED`인 경우만 쓰도록 제한한다. 기기 확인 상태를 클라이언트가 임의로 저장할 수 없다.

저장 가능한 필드는 행정구역 코드, 정확도 구간, 경계 데이터 버전, 확인·만료 시각이다. 원시 위도·경도 필드는 없다.

## 개인정보 판정

| 항목 | 상태 |
| --- | --- |
| 사용자 직접 입력 동네 | 코드 확인 |
| 원시 좌표 수집 | 구현 없음 |
| 원시 좌표 서버 전송 | 구현 없음 |
| 백그라운드 위치 | 구현 없음 |
| 기기 위치 확인 | 기능 플래그만 존재 |
| 공식 경계 라이선스 검토 | `BLOCKED_EXTERNAL` |
| 실제 위치 권한·정확도·모의 위치 검증 | `NOT_RUN` |
| 실제 Supabase 동네 RLS 검증 | `BLOCKED_EXTERNAL` |

## 활성화 전 조건

1. 공식 행정구역 경계의 이용 조건과 표시 의무를 확인한다.
2. 사용자가 버튼을 누른 순간에만 사용 중 위치 권한을 요청한다.
3. 좌표는 기기 안에서만 경계 판정에 사용하고 즉시 폐기한다.
4. 서버에는 행정구역 코드와 최소한의 검증 메타데이터만 전달한다.
5. 사용자 화면에는 `현재 위치로 동네 확인`이라고 표시하고 실거주·법적 주소 인증으로 표현하지 않는다.
6. 권한 거부·낮은 정확도·모의 위치·오프라인·경계 미일치 흐름을 실기기에서 검증한다.

## 현재 운영 가능 판정

사용자 직접 선택 방식만 사용할 수 있다. 기기 위치 확인은 코드·법률·데이터 라이선스·실기기 검증이 끝날 때까지 `BLOCKED_EXTERNAL`이다.
