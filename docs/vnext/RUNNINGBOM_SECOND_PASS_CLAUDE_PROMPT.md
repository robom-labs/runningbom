# 러닝봄 vNext 2차 제품 재설계 및 구현 프롬프트

당신은 `robom-labs/runningbom`의 2차 제품·모바일 구현 담당자다. 이 문서는 사용자의 말들을 그대로 기능 목록으로 옮기라는 명령이 아니다. 최신 `main`과 현재 vNext 구현을 독립적으로 읽고, 아래 제품 원칙에 맞지 않는 부분은 더 나은 판단으로 수정하라.

## 이번 작업의 목표

러닝봄을 단순한 대회 목록이나 기능 데모가 아니라 다음 세 가지가 자연스럽게 연결되는 한국 러너용 앱으로 정리한다.

1. **대회**를 빠르게 찾고 공식 접수 정보를 확인한다.
2. **러닝화**를 한국에서 실제 구매할 수 있는 기준으로 비교한다.
3. **코치**와 기록을 통해 오늘의 달리기를 시작한다.

현재 Google Play 비공개 테스트 트랙과 테스터는 절대 변경하지 않는다. Play 업로드, 트랙 게시, 테스터 수정, versionCode 변경은 이번 작업 범위 밖이다. 기존 대회 알림·딥링크·오프라인 fallback도 회귀시키지 않는다.

## 시작 전 확인

1. 최신 `origin/main`, `git status`, 열린 PR, 현재 Android/웹 배포 상태를 확인한다.
2. 아래 파일과 실제 caller·테스트를 모두 읽는다.
   - `apps/mobile/app/navigation/AppNavigator.tsx`
   - `apps/mobile/app/screens/explore/ExploreScreen.tsx`
   - `apps/mobile/domains/races/RaceScreen.tsx`
   - `apps/mobile/domains/shoes/catalog.ts`
   - `apps/mobile/domains/shoes/ShoeScreen.tsx`
   - `apps/mobile/app/screens/start/StartScreen.tsx`
   - `apps/mobile/domains/coaching/*`
   - `apps/mobile/app/screens/community/*`
   - `apps/mobile/app/screens/my/*`
   - `apps/mobile/services/supabase/*`
   - `apps/mobile/src/races.ts`, `apps/mobile/src/data/races.json`
   - `scripts/*race*`, `scripts/*shoe*`, `.github/workflows/*`
3. 이미 해결된 기능은 다시 만들지 말고, 실제 화면과 데이터가 어긋난 것만 고친다.
4. 수정 전에 `docs/vnext/RUNNINGBOM_SECOND_PASS_DECISIONS.md`에 발견한 문제, 채택안, 제외안을 기록한다.

## 실제로 확인된 현재 문제

- 탐색 최상단이 `대회 | 러닝화 | 출시예정`이라 ‘출시예정’이 러닝화와 분리돼 있다.
- 러닝화 정본은 8개뿐이며, 다수가 일본·미국·영국·베트남 공식 URL로 연결된다. 한국 사용자에게 외국 스토어를 기본 CTA로 보내면 안 된다.
- `upcoming-shoes.json`은 비어 있는데 출시예정 화면 자체는 존재한다. 과거 출시 제품을 출시예정으로 보이게 하거나 빈 화면을 노출하지 않는다.
- 대회 데이터는 `distances` 배열을 보존하지만, 카드/카운트가 사용자가 느끼기에 거리별 개별 대회처럼 보일 수 있다.
- 현재 시작 화면의 러닝 유형은 너무 많고 이름이 비슷하다.
- 현재 기본 코칭은 필요한 정보량과 말투가 충분히 코치처럼 느껴지지 않을 수 있다. 단, 센서·카메라·GPS가 없는 상태에서 실시간 자세 분석이나 부상 예방을 약속하면 안 된다.
- Supabase 환경 변수나 provider 설정이 없으면 커뮤니티/로그인 기능이 `CORE_ONLY`로 안전하게 비활성화된다. 이를 기능 오류처럼 감추지 말고, 설정 전에도 앱의 핵심 사용 경험이 완성되도록 한다.

## 최종 정보 구조

하단 5탭을 유지하지 않는다. 앱 상단 왼쪽의 햄버거 버튼으로 **왼쪽 Drawer**를 열며, Drawer는 길게 나열하지 말고 다음 세 묶음만 보여 준다.

| 묶음 | 항목 | 목적 |
| --- | --- | --- |
| 달리기 | 홈, 오늘의 코치, 내 기록 | 오늘 달릴 행동을 빠르게 시작 |
| 찾기 | 대회, 러닝화 | 접수와 장비 탐색 |
| 함께 | 커뮤니티, 크루 | 로그인 선택 기능 |

- 상단 오른쪽에는 항상 프로필 아바타를 둔다. 로그인 전에는 `나의 기록`으로, 로그인 뒤에는 프로필로 연결한다.
- 현재 화면의 상태와 스크롤 위치를 보존한다.
- 작은 화면에서 Drawer는 overlay, 태블릿에서는 compact rail로 확장할 수 있다.
- ‘메뉴 세 개’ 요구는 화면을 세 개로 제한하라는 뜻이 아니다. 기능을 세 개의 이해 가능한 그룹으로 압축하라는 뜻으로 해석한다.

## 1. 대회는 예전 정본을 그대로 복원하고 신뢰성을 유지한다

기존 대회 데이터·알림·필터·외부 링크는 보존한다. 이번 범위에서 대회 UI는 새로 발명하지 않는다. vNext 전 `outputs/pushrun-site/app.js`와 변경 기록에 있던 정본을 읽고, 다음 구조를 네이티브와 웹에 똑같이 복원한다.

### 반드시 지킬 대회 화면 구조

1. 거리 필터는 **가로 스크롤이 아닌 2행 × 3열**이다.
   - 첫째 행. `전체 | 풀코스 | 하프`.
   - 둘째 행. `10K | 5K | 트레일`.
   - 위 두 행은 화면상 두 행일 뿐, 선택값은 하나의 `distanceFilter`다. `풀코스`와 `10K`가 동시에 선택되는 잘못된 다중 선택을 만들지 않는다.
2. 그 아래 접수 상태 필터는 한 행이다.
   - `전체 | 접수 중 | 접수 예정`.
3. 지역·검색·정렬은 기본 3행을 흐리지 않게 검색창 옆 `지역` 또는 추가 조건 패널에 넣는다. 지역 기능은 제거하지 않는다.
4. 카드 목록은 세로형이며, 카드마다 상태 색선/상태 배지, 행사명, 날짜·지역·장소, 거리 배지, 가장 중요한 접수 일정, 상황에 맞는 알림/공식 페이지 행동을 둔다.
5. 카드의 `자세히 보기`는 한 카드만 펼치는 아코디언이다. 펼침 내용은 출발 장소, 종목별 접수창, 대회 일정, 주최·규모, 공식 출처 순서다. 긴 데이터를 접힌 카드에 밀어 넣지 않는다.
6. `대회 N개`는 필터 결과의 **고유 eventId 수**다. 5K·10K·하프 종목 수나 접수창 수로 세지 않는다. 행사 안의 여러 거리 값은 카드 태그와 상세의 접수창으로만 보인다.

### 데이터 규칙

- 하나의 행사 = 하나의 `eventId`다. 5K·10K·하프는 하나의 행사 카드 안의 거리 배지/접수창으로 표현한다.
- 목록의 ‘대회 N개’는 행사 수여야 한다. 거리 수를 세면 안 된다.
- 중복 후보는 이름 정규화, 개최일, 지역/장소, 공식 URL을 조합해 검토 큐로 보내고, 자동으로 서로 다른 행사를 합치지 않는다.
- 공식 대회 URL이 있으면 최우선으로 표시한다. 집계 출처만 있으면 CTA를 `정보 출처 열기`로 정확히 표기한다.
- 취소·매진·접수마감은 기본 탐색에서 숨기되, 이미 알림을 설정한 사용자는 상태 변경을 알 수 있어야 한다.
- 6시간 자동 갱신은 유지하되, 소스별 마지막 확인 시각과 링크 실패를 기록한다. 단순 HTTP 200만으로 일정이 정확하다고 단정하지 않는다.

### 대회 카드

한 카드에는 아래만 우선 배치한다.

- 접수 상태와 D-day
- 행사명
- 날짜 · 지역 · 장소
- 거리 배지 묶음
- 접수 기간 또는 접수 시작 시각
- `접수 알림`과 `공식 페이지` 두 행동
- `자세히 보기` 아코디언

긴 설명, 출처 상세, 세부 접수창은 펼침 또는 상세로 보낸다. 한 행사 안에 여러 거리별 접수 시각이 다르면 알림을 거리/창별로 선택하게 한다.

## 2. 러닝화는 하나의 한국 구매 중심 허브로 합친다

`출시예정`을 최상위 탐색 탭에서 제거한다. 러닝화 안에 다음 컬렉션을 둔다.

1. **내 목적에 맞는 신발**. 4문항 Finder.
2. **데일리·입문**. 편안한 일상/초보 러닝.
3. **쿠션·장거리**. 긴 거리와 회복성 러닝.
4. **훈련·템포**. 빠른 훈련용.
5. **레이스·카본**. 대회용. 카본 여부는 공식 사양에서만 표시.
6. **트레일**. 별도 지면용.
7. **스테디셀러**. 한국 공식 스토어에서 현재 판매가 확인된 제품만.
8. **국내 출시 예정**. 한국 공식 출처에 미래 출시일 또는 예약 판매가 명시된 제품만.

`글로벌 발표 · 국내 일정 미확인`은 출시예정에 넣지 않는다. 필요하면 러닝화 상세의 작은 정보 섹션으로만 보인다.

### 필터와 추천 기준

- 러닝 목적. 처음 달리기, 매일 3~10K, 10~20K 훈련, 하프/풀 준비, 기록 도전, 트레일.
- 착화 성향. 쿠션, 균형, 반응성, 안정감.
- 지면. 로드, 트레드밀, 트레일.
- 예산은 **공식 한국 가격을 확보한 모델에만** 작동한다.
- 발 모양·회내·부상 위험을 진단하거나 의료적으로 추천하지 않는다.
- 결과마다 ‘추천 이유’와 ‘고려할 점’을 한 줄씩 제공하고, 확정 추천이나 최저가 표현은 쓰지 않는다.

### 구매 CTA

- 각 모델의 기본 CTA는 한국 공식 판매 URL이다. `KR 공식 확인`이 없는 제품은 일반 목록의 기본 카드에서 숨기거나 ‘해외 공식 정보’로 명확히 격리한다.
- `네이버 가격 보기`, `쿠팡에서 찾기`는 현재 가격을 앱이 보장하거나 긁어오는 기능이 아니다. 모델명으로 만든 외부 검색 링크로만 제공하며 OS 브라우저에서 연다.
- 제휴 링크, WebView, ‘최저가’ 문구, 재고 보장은 금지한다.
- 공식 가격은 `priceKrw`, `priceCheckedAt`, `priceSourceUrl`이 모두 있을 때만 표시한다.

### 데이터 운영

- 제품 수 목표를 억지로 채우지 않는다. 1차 목표는 6~8개 브랜드의 **국내 공식 검증 모델 24~32개**다.
- 각 모델에는 `availability`(current/upcoming/global_only/archived), `koreaOfficialUrl`, `officialFacts`, `officialPriceKrw?`, `priceCheckedAt?`, `verifiedAt`, `sourceKind`를 둔다.
- 한국 공식 페이지가 사라지거나 품절/단종을 확인하면 archived로 옮기고 기본 목록에서 숨긴다.
- 정기 작업은 신제품을 바로 게시하지 않는다. 공식 한국 도메인 allowlist 조회 → schema 검증 → diff 생성 → 수동 승인 큐 → 정본 반영 순서다.
- 이용약관/robots/API 허용 범위를 벗어난 크롤링을 추가하지 않는다.

## 3. 코치는 ‘말을 많이 하는 앱’이 아니라 ‘곁에서 페이스를 잡아 주는 앱’이어야 한다

사용자는 더 풍부한 코칭을 원하지만, 쉬지 않고 말하면 러닝과 안전을 방해한다. 따라서 코칭 밀도를 사용자가 고르게 한다.

### 사용자에게 보이는 4개 모드

- 처음 달리기. 걷기와 달리기를 섞음.
- 편하게 달리기. 기본 데일리 러닝.
- 목표 페이스. 템포/조금 빠른 달리기.
- 회복 걷기. 부담 없는 움직임.

인터벌, 트레드밀, 대회 전 등은 `더보기`에만 두고 기본 선택지에 나열하지 않는다.

### 코칭 밀도

- 조용히. 시작·전환·마무리 위주.
- 기본. 약 3~5분 간격과 페이즈 전환.
- 코치처럼. 약 60~90초 간격의 짧은 호흡·보폭·상체 긴장 완화·현재 노력도 점검.

어떤 수준도 감시·의료 진단·실시간 자세 분석처럼 표현하지 않는다. 예:

- 가능. `어깨 힘을 가볍게 풀고, 발걸음을 짧고 편안하게 이어가 볼까요?`
- 금지. `무릎 각도가 잘못됐어요`, `부상을 예방합니다`, `현재 심박이 높습니다`.

실제 Android 네이티브 TTS·foreground service에서 화면 잠금, 블루투스 해제, 통화 뒤 재개를 검증하지 못했다면 해당 기능을 출시 완료로 표시하지 않는다.

## 4. 프로필·커뮤니티·배지는 가볍고 정직하게

- 마이는 최상단 프로필 카드와 저장 버튼을 유지한다. 지금의 로컬 프로필 저장도 먼저 완성된 경험으로 다듬는다.
- 로그인 provider가 비활성인 이유를 코드와 환경 변수에서 정확히 확인한다. 설정값/심사가 없으면 연결 버튼을 누를 수 없게 두거나 ‘준비 중’으로 숨기며, 가짜 로그인 성공을 만들지 않는다.
- 커뮤니티는 로그인·Supabase가 준비되기 전에는 읽기 전용 또는 안내 상태여야 하며 빈 피드를 실제 커뮤니티처럼 꾸미지 않는다.
- 배지는 홈에 여러 개를 늘어놓지 않는다. `첫 시작`, `꾸준함`, `거리/세션`, `대회·커뮤니티` 네 묶음으로 보관함을 구성한다.
- 대표 배지 1개만 프로필에 노출한다. `주 3회`는 주간 달성 중 하나일 뿐 전체 보상 체계가 아니다.

## 구현 순서

1. vNext 이전 대회 화면 정본을 Git history에서 대조하고, 위 2행 거리 필터 + 1행 접수 상태 + 카드 아코디언을 회귀 테스트로 고정한다. 이벤트 단위 수를 테스트로 증명한다.
2. Drawer 기반 내비게이션을 추가하고, 기존 5개 화면을 세 그룹으로 매핑한다. 딥링크와 화면 상태 보존을 검증한다.
3. Explore를 `대회 | 러닝화` 두 최상위 탭으로 줄인다.
4. 러닝화 데이터 모델·한국 공식 링크 규칙·컬렉션·Finder를 구현한다. 잘못된 해외 기본 링크와 과거 출시예정 분류를 제거한다.
5. 코칭 유형과 안내 밀도를 단순화한다. 음성 큐는 실제 기기 검증 전까지 과장하지 않는다.
6. 프로필·배지·커뮤니티의 빈 상태와 provider 상태를 정리한다.
7. 단위 테스트, 타입체크, 린트, Android/웹 빌드, 320/390/430/768px 또는 동등한 화면 검증을 실행한다.

## 금지

- Play Console, EAS Submit, 비공개 테스트 트랙, 테스터, production을 바꾸지 않는다.
- 검증되지 않은 대회, 출시일, 가격, 재고, 카본 여부를 하드코딩하지 않는다.
- 해외 사이트를 한국 기본 구매 링크로 사용하지 않는다.
- 네이버/쿠팡 가격을 수집해 최저가·실시간 재고처럼 표시하지 않는다.
- 러닝 자세·부상·심박을 실제로 분석하는 것처럼 말하지 않는다.
- 기존 사용자의 알림, 관심 대회, 로컬 기록, package/signing, deep link를 깨지 않는다.

## 결과 보고

1. 수정한 실제 사용자 문제와 원인.
2. 대회/신발/코치/내비게이션별 변경 파일.
3. 한국 공식 검증 제품 수와 제외한 해외/미확인 제품 수.
4. 대회가 행사 단위로 세어지는 테스트 증거.
5. 실행한 테스트·실제 실행 결과·실행하지 못한 기기 검증.
6. Play 관련 변경이 없다는 증거.
