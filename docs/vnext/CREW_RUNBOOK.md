# 크루 기능 구현·운영 현황

## 현재 판정

크루의 데이터 구조, 권한 함수, 앱 서비스 함수는 구현돼 있다. 사용자가 크루를 검색하고 생성·가입·관리하는 완성 화면과 실제 Supabase 연결 검증은 아직 없다.

| 영역 | 상태 |
| --- | --- |
| 테이블·RLS·RPC | 코드 확인 |
| 앱 서비스 함수 | 코드 확인 |
| 크루 탭 안내 화면 | 코드 확인 |
| 완성된 크루 사용자 흐름 | 미구현 |
| 실제 Supabase 역할별 검증 | `BLOCKED_EXTERNAL` |
| 실제 크루 생성·가입·소유권 이전 | `NOT_RUN` |

## 현재 데이터 계약

### 크루

- 공개 유형은 `PUBLIC`, `APPROVAL`, `PRIVATE`다.
- 정원은 3~500명이다.
- 상태는 `ACTIVE`, `ARCHIVED`, `DELETING`이다.
- 이름은 2~30자이며 소개는 최대 1,000자다.

### 역할

- 역할은 `OWNER`, `ADMIN`, `MODERATOR`, `MEMBER`, `PENDING`, `BANNED`다.
- 크루 생성 RPC는 호출자를 소유자와 `OWNER` 멤버로 같은 트랜잭션 안에 기록한다.
- 마지막 소유자는 일반 탈퇴 정책으로 삭제할 수 없다.
- 소유권 이전은 현재 소유자만 실행할 수 있으며 새 소유자는 활성 멤버여야 한다.
- `ADMIN`은 다른 `ADMIN`을 관리하거나 `ADMIN`으로 승격할 수 없다.
- 소유자 변경은 일반 역할 변경 RPC가 아니라 전용 소유권 이전 RPC를 사용한다.

### 일정과 참석

- 일정 제목은 2~80자다.
- 선택 정원은 1~500명이다.
- 일정 상태는 `ACTIVE`, `CANCELLED`, `COMPLETED`다.
- 참석 상태는 `ATTENDING`, `MAYBE`, `DECLINED`, `WAITLIST`다.
- 공개 장소와 멤버 장소를 별도 필드로 저장한다.
- 활성 멤버만 일정 조회와 참석이 가능하도록 정책과 조회 함수가 연결돼 있다.
- 소유자·관리자·운영자만 일정을 생성·수정할 수 있다.

## 현재 앱 서비스

다음 함수가 존재한다.

- 크루 생성
- 가입 요청
- 멤버 역할 변경
- 일정 생성
- 일정 수정
- 참석 상태 저장

모든 쓰기 함수는 커뮤니티 모드가 `NORMAL`일 때만 실행된다. Supabase가 없으면 `CORE_ONLY`, 별도 쓰기 모드를 지정하지 않은 Supabase 환경은 기본 `READ_ONLY_COMMUNITY`다.

## 현재 화면

`커뮤니티 → 크루`에는 서버 연결 상태와 설명 카드만 있다. `크루 찾기` 버튼은 소셜 기능 플래그가 켜지고 커뮤니티 모드가 `NORMAL`일 때만 활성화되지만, 현재 버튼 동작은 연결되지 않았다.

따라서 다음 사용자 흐름은 아직 제공되지 않는다.

- 크루 검색·상세 보기
- 생성 폼
- 가입 승인·거절
- 초대
- 멤버 관리
- 공지·크루 피드
- 일정 목록·참석 화면
- 소유권 이전
- 크루 보관·삭제

번개런, 실시간 위치, 1:1 메시지는 구현 대상에서 제외돼 있으며 코드에도 제공 화면이 없다.

## 활성화 전 검증 항목

1. 서로 다른 소유자·관리자·운영자·멤버·대기자 JWT로 RLS와 RPC를 검증한다.
2. 관리자의 관리자 승격·관리 차단과 소유자 탈퇴 차단을 실제 데이터베이스에서 확인한다.
3. 비공개 크루와 멤버 전용 장소가 비멤버에게 노출되지 않는지 확인한다.
4. 정원 도달 시 대기 처리 규칙을 구현하고 검증한다.
5. 크루 삭제 수명주기와 소유권 이전 실패 복구를 구현한다.

## 운영 가능 판정

현재 크루는 서버 기반을 검토할 수 있는 코드 단계다. 일반 사용자가 사용할 수 있는 완성 기능이나 실제 운영 기능으로 판단하면 안 된다.
