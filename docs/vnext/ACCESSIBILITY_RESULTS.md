# 접근성 코드 점검 결과

## 점검 범위

현재 React Native 코드의 접근성 속성, 터치 영역, 반응형 분기, 입력 흐름을 정적 점검했다. TalkBack, 시스템 큰 글자, 화면 확대, 실제 휴대전화·태블릿 렌더링은 실행하지 않았다.

## 코드에서 확인한 항목

| 항목 | 결과 | 근거 |
| --- | --- | --- |
| 공용 버튼 터치 높이 | 코드 확인 | 기본 버튼 `minHeight`가 48이다. |
| 선택 chip 터치 높이 | 코드 확인 | chip `minHeight`가 48이다. |
| 버튼 역할·비활성 상태 | 코드 확인 | `accessibilityRole`과 `accessibilityState`를 사용한다. |
| 선택 상태 | 코드 확인 | chip이 선택 상태를 접근성 상태로 제공한다. |
| 주요 제목 | 코드 확인 | 공용 섹션 제목에 header 역할이 있다. |
| 상태 변경 안내 | 코드 확인 | 홈·대회·시작·커뮤니티·마이에 live region이 있다. |
| 입력 접근성 이름 | 코드 확인 | 대회·러닝화 검색, 코칭 시간, 동네 입력 등에 이름이 있다. |
| 키보드 회피 | 코드 확인 | 시작 화면이 `KeyboardAvoidingView`를 사용한다. |
| 태블릿 내비게이션 | 코드 확인 | 폭 768 이상에서 하단 탭을 왼쪽 레일로 전환한다. |
| 콘텐츠 최대 폭 | 코드 확인 | 주요 화면이 최대 960 폭을 사용한다. |
| 다크 모드 | 미구현 | 앱 설정과 테마가 밝은 화면으로 고정돼 있다. |

## 실행하지 않은 검증

| 검증 | 상태 |
| --- | --- |
| Android TalkBack 전체 이동 | `BLOCKED_EXTERNAL` |
| 키보드만으로 전체 탐색 | `NOT_RUN` |
| 시스템 글자 125% | `BLOCKED_EXTERNAL` |
| 시스템 글자 200% | `BLOCKED_EXTERNAL` |
| 320·390·430px 실제 렌더 | `NOT_RUN` |
| 768px 태블릿 실제 렌더 | `NOT_RUN` |
| 화면 확대 200% | `BLOCKED_EXTERNAL` |
| 색 대비 자동 검사 | `NOT_RUN` |
| 초점 복원·모달 초점 가두기 | `NOT_RUN` |
| 다크 모드 | 미구현 |

## 정적 점검에서 남은 위험

- 모든 화면이 공용 버튼만 사용하지 않으므로 개별 `Pressable`의 실제 터치 영역은 실기기 확인이 필요하다.
- 시스템 글자가 커질 때 가로 chip·배지 행과 탭 레이블이 잘리는지 검증하지 않았다.
- 모달을 닫은 뒤 이전 요소로 초점이 돌아오는지 확인하지 않았다.
- 밝은 테마만 구현돼 있어 운영체제 다크 모드와 일치하지 않는다.
- 화면 읽기 순서와 반복되는 카드의 접근성 설명은 TalkBack으로 검증해야 한다.

## 현재 판정

접근성 속성과 기본 터치 영역의 코드 기반은 확인했다. 실제 접근성 합격 판정은 할 수 없으며, 실기기 TalkBack과 큰 글자 검증은 `BLOCKED_EXTERNAL`이다.
