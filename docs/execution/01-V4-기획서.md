## 0. 두 문장

> **러닝라이프는 대회를 찾아 준다. 러닝봄은 그 대회까지 데려다준다.**
> **그리고 그 대회를 뛸 신발까지, 가격까지 보여 주고 골라 준다.**

대회 정보는 누구나 모을 수 있습니다. 우리가 이미 가진 것 — **계획 40개 · 훈련 103개 ·
도전 40개 · 보조 프로젝트 20개 · 안전 검증기 · 귀에 들리는 음성 코치** — 는 아무도
가지고 있지 않습니다. V4는 그 자산을 **보이게** 만드는 작업입니다.

지금 문제는 기능이 없는 것이 아니라 **기능이 안 보이는 것**입니다.

### 0.1 러닝화 — V4의 두 번째 기둥

회장 지시 원문 요지입니다.

> "이 사이트는 어찌 보면 **러닝화를 사는 걸 도와주는 중계 사이트**가 되는 거야."
> "**가격이 중요해. 무조건 나와야 해.** 사람들 입장에서 생각해 봐. **신발 가격에 따라
> 고민하는 게 대부분**이야."
> "러닝화는 여러 인터넷 정보에서 **주기적으로 취합**해서 가격 가져오면 되잖아.
> 어차피 **정가**로 가져오는 건데."
> "**신발 순위**도 메인 화면 아래쪽에 있고 얼마나 좋아."
> "러닝화 **사진**도 나오고, 대회 **포스터**도 나오고."

이 지시가 아래 넷을 만듭니다.

## 2. 러닝라이프에서 배울 것 / 넘어설 것

관찰은 회장이 보내 준 스크린샷을 근거로 합니다. 문장·훈련표·상표는 **가져오지 않습니다.**
가져오는 것은 **구조와 원리**뿐입니다.

| 그쪽이 잘하는 것 | 우리가 할 것 (한 단계 위) |
|---|---|
| 큰 숫자 하나 + 보조 둘 | 같게 하되, **지금 구간에 맞는 숫자**를 크게 (걷는 중엔 남은 시간, 뛰는 중엔 페이스) |
| 알이 부화하는 게임화 | 알 대신 **내 기록으로 자라는 지도** (§8) |
| 끝나고 이모지 5개로 난이도 | 이모지 대신 **말로 고르는 3지선다 + 몸 상태 태그** (§9) |
| "총 16회 중 1회차" 한 줄 | 같게 하되 **다음 회차가 언제인지**까지 (§6.3) |
| 대회 카드에 마감임박 배지 | 같게 하되 **내 계획과 맞는지**까지 (§6.2) |
| 달력에 대회 있는 날 점 | 같게 하되 **내 훈련일과 겹쳐서** 표시 |
| 첫 진입 툴팁 "첫 플랜 만들어볼까요?" | 툴팁 대신 **온보딩 4단계로 목표까지 받고 계획을 바로 깔아 줌** (§5) |
| 케이던스: 흔한 값 3개 먼저, 전체는 아래 | **이 패턴을 앱 전체 선택 화면의 표준으로** (§4.6) |
| 러닝화 목록 | **용도별 추천 + 가격 + 내 기록 기반 매칭** (§6.4) |

**우리에게만 있는 것 (러닝라이프에 없음)**
- 귀로만 따라 할 수 있는 음성 코치 (계획 회차 내내 21초 이상 조용하지 않음)
- 위험한 계획을 만들지 못하게 막는 안전 검증기
- 오늘 뭘 할지 하나만 골라 주는 적응형 제안 (쉬라고 말할 줄 앎)
- 걷기만 해도 인정하는 도전 40개

→ **이 넷을 홈 화면 첫 화면에서 바로 느끼게 만드는 것이 V4의 핵심입니다.**

## 3. 새 정보구조 (IA)

### 3.1 지금 문제

- 프로그램 화면 하나에 오늘 제안 · 계획 고르기 · 도전 · 훈련 103개 · 보조 프로젝트 ·
  9주 진행 · 대회 계획이 **세로로 전부** 쌓여 있습니다. 회장 표현 그대로 "너무 길다".
- 무엇이 중요한지 화면이 말해 주지 않습니다.

### 3.2 새 구조 — 하단 탭 5개

```
홈        오늘 할 것 하나 + 이번 주 요약 + 성장
대회      캘린더/리스트 + 내 목표 대회
훈련      계획 · 오늘 훈련 · 도전 · 챙길 것 (4개 칸으로 분리)
러닝화    용도별 추천 · 내 신발 · 전체 찾기
나        기록 · 성장 · 설정
```

**규칙**
- 한 탭에 **세로 스크롤 3화면**을 넘기지 않습니다. 넘으면 안으로 밀어 넣습니다.
- 각 탭 첫 화면은 **카드 4장 이내**.
- 목록이 5개를 넘으면 "더 보기"로 접습니다.

### 3.3 훈련 탭 안쪽 (긴 화면 해체)

지금 한 화면에 있던 것을 **네 칸**으로 나눕니다.

```
훈련
├── 지금 하는 계획      진행률 · 다음 회차 · [오늘 회차 시작]
├── 오늘 한 번만        추천 4개 → [전체 103개]
├── 도전                진행 중 3개 → [전체 40개]
└── 챙길 것             하던 것 1개 → [전체 20개]
```

각 칸은 **접힌 상태가 기본**이고, 펼치면 그 칸만 보입니다.

## 4. 디자인 시스템 — "조잡함"을 없애는 규칙

### 4.1 지금 조잡해 보이는 진짜 이유

1. 카드마다 글자 크기·간격이 제각각 → 눈이 쉴 곳이 없음
2. 그림이 하나도 없음 → 전부 글자라 밀도가 높아 보임
3. 강조가 너무 많음 → 다 강조하면 아무것도 강조가 아님
4. 버튼이 작고 서로 붙어 있음 → 누르기 불편

### 4.2 여백 (가장 큰 개선)

- 카드 안 위아래 **20px**, 좌우 **20px** 고정
- 카드 사이 **12px**
- 화면 좌우 **20px**
- 관련 있는 것끼리는 **8px**, 다른 덩어리는 **20px** — 간격으로 묶음을 표현

### 4.3 글자 — 한 화면에 3단계만

| 쓰임 | 크기 | 굵기 |
|---|---:|---|
| 화면 제목 | 28 | 800 |
| 카드 제목 | 20 | 700 |
| 본문 | 16 | 400 |
| 보조 | 13 | 400 |

**한 카드 안에 4단계 이상 쓰지 않습니다.**

### 4.4 색 — 강조는 한 화면에 하나

- 바탕 크림, 글자 먹색, 강조 1개(따뜻한 주황)
- **경고색(빨강)은 마감임박·위험에만.** 그 밖에는 쓰지 않습니다.
- 성공색(초록)은 달성에만.

### 4.5 누르는 것

- 모든 누를 수 있는 것은 **최소 높이 48px, 좌우 여백 16px**
- 버튼 두 개가 나란히 있으면 **사이 12px**
- 주 버튼은 화면당 **하나**. 나머지는 테두리 버튼이나 글자 버튼.
- 목록 항목 전체가 눌리게 (작은 화살표만 누르게 하지 않음)

### 4.6 선택 화면 표준 — "흔한 것 3개 먼저"

러닝라이프의 케이던스 화면에서 배운 패턴을 **앱 전체 표준**으로 삼습니다.

```
[ 많이 고르는 것 3개 ]     ← 큰 칩
전체 보기 ▾                ← 눌러야 펼쳐짐
```

적용: 계획 고르기, 훈련 고르기, 목표 시간, 케이던스, 러닝화 필터.

### 4.7 그림 — 회장이 말한 "사진"을 어떻게 만드는가

회장 지시는 **"러닝화 사진도 나오고 대회 포스터도 나온다"** 입니다.
동시에 우리 규칙은 **새 월 고정비 0 · 외부 CDN 0 · 남의 이미지 무단 사용 0** 입니다.
둘 다 지키는 답은 하나뿐입니다 — **앱 안에서 그립니다.**

#### 4.7.1 세 종류

| 종류 | 무엇 | 어떻게 |
|---|---|---|
| **신발 그림** | 러닝화 카드·상세의 시각물 | 옆모습 실루엣을 `react-native-svg`로 그리고, **밑창 두께·굽 경사·앞코 들림·색**을 그 신발의 실제 성격값에서 계산 |
| **대회 포스터** | 대회 카드 상단 배너 | 대회 **거리·지역·계절·시각**에서 만들어 내는 그라데이션 + 큰 글자 조판 |
| **훈련 그림** | 계획·훈련 카드 | 걷기·달리기·오르막·러닝머신·회복을 도형과 색으로 |

#### 4.7.2 신발 그림이 "진짜처럼" 보이려면

단색 도형 하나로는 조잡합니다. 신발 그림은 **최소 6개 레이어**를 쌓습니다.

```
1) 아웃솔  (바닥, 짙은 색, 앞뒤로 살짝 들림)
2) 미드솔  (가장 두꺼운 층 — 쿠션 등급이 두께를 정함)
3) 플레이트(있는 신발만 — 미드솔 안에 얇은 선 하나)
4) 어퍼    (갑피 — 브랜드 색)
5) 뒷굽 카운터 + 힐탭
6) 끈 4~5줄 + 스우시 자리(빈 곳으로 둠 — 상표는 그리지 않음)
```

- **성격값이 그림을 바꿉니다.** 쿠션 최상급은 미드솔이 두껍고, 대회용은 앞코가 크게
  들리고, 트레일은 아웃솔에 러그 이가 생깁니다. → 카드를 훑기만 해도 종류가 구분됩니다.
- **브랜드 로고·상표·실제 제품 사진은 절대 그리지 않습니다.** 색과 형태만 씁니다.
- 그림 밑에 항상 한 줄: `그림은 형태를 나타낸 것으로, 실제 제품과 다를 수 있어요.`

#### 4.7.3 대회 포스터

```
┌────────────────────────────┐
│  ▓▓▓ 계절색 그라데이션 ▓▓▓   │
│         10 K              │  ← 거리를 가장 크게
│    서울 · 11월 2일         │
│  제23회 서울마라톤          │
└────────────────────────────┘
```

- 색은 **월(계절)** 에서 정합니다. 봄 연둣빛 / 여름 청록 / 가을 주황 / 겨울 남색
- 거리(5K·10K·하프·풀)에 따라 조판 무게가 달라집니다
- 주최 측 실제 포스터 이미지는 **쓰지 않습니다.** 저작권과 월 고정비 둘 다 걸립니다

#### 4.7.4 공통 규칙

- **외부 이미지 다운로드 없음. 번들 사진 파일 없음.** 전부 벡터로 그립니다(APK 증가 0).
- 그림은 순수 함수여야 합니다: `shoeArtSpec(shoe) → 레이어 값`, `raceArtSpec(race) → 색·조판`.
  → 테스트가 그림 규칙을 검증할 수 있습니다(같은 신발이면 언제나 같은 그림).
- 다크 모드에서도 대비가 유지되어야 합니다.

## 5. 온보딩 — 처음 3분

지금은 앱을 열면 아무것도 묻지 않고 계획 40개를 보여 줍니다. 그래서 아무도 시작하지 않습니다.

### 5.1 4단계 (각 화면에 질문 하나)

```
1. 어떻게 부를까요?          이름 (건너뛰기 가능)
2. 지금 어느 정도세요?        6개 중 하나 (기존 selfPickLevels 재사용)
3. 무엇을 하고 싶으세요?      건강 / 5km / 10km / 대회 / 그냥 꾸준히
4. 일주일에 몇 번 나갈 수 있어요?   2 / 3 / 4
```

### 5.2 끝나면 바로

- 고른 값으로 **계획을 자동으로 하나 깔아 줍니다** (`recommendFamilies` 1순위)
- 첫 회차를 **"오늘 시작하기"** 버튼 하나로 바로 보여 줍니다
- 목표가 대회면 대회 탭으로 한 번 데려갑니다

### 5.3 지킬 것

- **모든 단계 건너뛰기 가능.** 건너뛰면 안전한 기본값으로 갑니다.
- 로그인 요구하지 않습니다. 이 기기에만 저장합니다.
- 4단계를 넘지 않습니다.

**"순위"라는 말을 쓰는 이상 근거를 밝힙니다.** 순위 헤더를 누르면 산식 설명이 열립니다.
근거 없는 순위는 신뢰를 한 번에 잃습니다.

- **참가비는 아는 대회만** 씁니다. 모르면 그 줄을 아예 빼고, 지어내지 않습니다.

- **리스트 / 캘린더** 전환 (러닝라이프와 같음)
- 캘린더에는 대회 점(주황) + **내 훈련일 점(회색)** 을 같이 찍습니다 ← 우리만
- 대회를 목표로 정하면 **훈련 계획이 그 날짜에 맞춰 다시 깔립니다** ← 우리만

### 6.4 러닝화 — V4에서 가장 크게 바뀌는 곳

회장이 특히 지목한 부분입니다. 지금은 **글자 목록**만 있습니다.
V4에서는 **사진(그림) · 가격 · 순위 · 중계**가 있는 화면이 됩니다.

#### 6.4.1 우리가 하는 일을 한 줄로

> **"러닝화를 사는 걸 도와주는 곳."**

우리는 신발을 팔지 않습니다. 재고도, 결제도, 배송도 없습니다.
우리가 하는 일은 셋입니다.

1. **내 기록에 맞는 신발을 골라 준다** (다른 곳은 못 합니다 — 우리만 기록을 가지고 있습니다)
2. **얼마인지 바로 알려 준다** (가격 때문에 고민하는 게 대부분이니까)
3. **공식 판매처로 데려다준다** (거기서 사는 것은 사용자와 판매처의 일)

→ 이 셋을 **한 화면 안에서** 끝내는 것이 목표입니다.

#### 6.4.2 첫 화면 — 용도별 갈래 + 가격대

```
어떤 신발을 찾으세요?

┌──────────┬──────────┬──────────┐
│  입문용   │  데일리   │  장거리   │
│ 처음 사면 │ 매일 편하게│ 오래 뛸 때│
├──────────┼──────────┼──────────┤
│  빠르게   │  대회용   │ 러닝머신  │
│ 속도 낼 때│ 대회 당일 │  실내     │
└──────────┴──────────┴──────────┘

가격으로 고를래요
[ ~10만원 ] [ 10~15만원 ] [ 15~20만원 ] [ 20만원~ ]
```

- 각 갈래에 **대표 3켤레만** 보여 주고 "전체 보기"(§4.6 표준).
- **가격대 칩을 갈래와 같은 크기로 첫 화면에 둡니다.**
  회장 말대로 "가격에 따라 고민하는 게 대부분"이라면, 가격은 필터 속에 숨을 게 아니라
  **입구 두 개 중 하나**여야 합니다.

#### 6.4.3 카드 한 장 — 가격은 반드시 있습니다

```
┌──────────────────────────────────┐
│  ╭────────────╮                  │
│  │  신발 그림   │  나이키 페가수스 41 │
│  │  (§4.7.2)   │  데일리 · 쿠션 보통  │
│  ╰────────────╯                  │
│                                  │
│  159,000원                       │ ← 정가 (가장 크게)
│  실구매 139,000 ~ 159,000원       │ ← 범위
│  2026년 7월 기준 · 나이키 공식      │ ← 언제·어디 기준인지
│                                  │
│  👟 주 20km 뛰는 지금에 맞아요      │ ← 매칭 이유
│  [ 자세히 ]      [ 공식몰에서 보기 ] │
└──────────────────────────────────┘
```

**가격 규칙 (V4에서 가장 엄격하게 지킬 것)**

| 규칙 | 이유 |
|---|---|
| **모든 카드에 가격이 있어야 합니다.** 예외 없음 | 회장 지시. 가격 없는 카드는 살지 말지 판단이 안 됩니다 |
| 큰 숫자는 **정가(공식 판매가)** | 실시간 최저가는 우리가 알 수 없습니다. 정가는 브랜드가 공표한 사실입니다 |
| 그 아래 **실구매 범위** | 실제로는 할인해서 삽니다. 범위가 있어야 판단이 됩니다 |
| **`2026년 7월 기준` 을 항상 같이** | 언제 값인지 모르는 가격은 거짓말이 됩니다 |
| **출처를 밝힙니다** (`나이키 공식`) | 어디서 온 숫자인지 말할 수 없으면 쓰지 않습니다 |
| 정가를 모르면 **그 갈래의 가격대 범위** | **비워 두지 않고, 지어내지도 않습니다.** 갈래의 가격대는 갈래에 대한 사실이지 그 신발의 값이 아니라서, 지어낸 값이 아니면서도 판단에 도움이 됩니다 |
| `최저가`·`최저가 보장` 같은 말 금지 | 우리가 보장할 수 없는 말입니다 |

**"가격 확인 중" 카드는 목록 맨 뒤로 내리고, 순위(§6.4.5)에는 올리지 않습니다.**
→ 확인 안 된 신발이 상위에 보이지 않으니, 가격 채우기가 자연히 우선순위가 됩니다.
→ 목표는 **가격 커버리지 100%**. 진척은 §6.6의 리포트로 매주 셉니다.

#### 6.4.5 순위 — 어떻게 매기는가

홈 아래쪽(§6.1.1)과 러닝화 탭 위쪽에 같은 순위가 나옵니다.

**산식 (전부 우리 데이터. 외부 판매량·협찬 없음)**

| 점수 | 무엇 | 비중 |
|---|---|---|
| 적합도 | 이 앱 사용자들의 실제 기록 분포와 얼마나 맞는지 | 40% |
| 가격 신뢰 | 가격이 확인되었는지, 최근에 확인했는지 | 20% |
| 정보 완성도 | 심화 필드 6개가 다 채워졌는지 | 20% |
| 국내 구입 | 국내 공식 판매 여부 | 20% |

- **가격 미확인 신발도 순위에는 나옵니다.** 처음 계획은 빼는 것이었는데, 구현하면서
  뒤집었습니다 — 123종 중 정가가 확인된 것이 **0종**이라, 빼면 순위가 통째로 비기 때문입니다.
  대신 "가격 확인" 20점을 못 받아 **자연히 아래로 밀립니다.** 채우면 올라가고 안 채우면
  내려가므로, 채울 이유가 구조에 들어갑니다.
- 순위에 오른 모든 줄에는 **반드시 숫자가 보입니다**(정가 아니면 가격대 범위).
- 순위 헤더를 누르면 **이 표가 그대로 열립니다.** 근거를 숨기지 않습니다.
- 순위는 **주 1회**만 바뀝니다(§6.6과 같은 주기). 매일 흔들리면 신뢰가 떨어집니다.
- **광고·협찬으로 순위를 바꾸지 않습니다.** 이 문장은 앱 안에도 씁니다.

#### 6.4.6 "사러 가기" — 중계는 이렇게 합니다

- 버튼 이름은 **`공식몰에서 보기`**. `최저가 보기`가 아닙니다.
- 항상 **브랜드 국내 공식 페이지**로 보냅니다(이미 `officialUrl`이 있습니다).
- 외부 브라우저로 열고, 돌아왔을 때 보던 자리를 그대로 유지합니다.
- **제휴 링크·수수료·추적 파라미터는 지금 넣지 않습니다.** 넣으려면 회장 승인이 먼저입니다.
- 열기 전에 한 줄: `러닝봄은 신발을 팔지 않아요. 공식 판매처로 이동해요.`

### 6.6 가격을 주기적으로 어떻게 가져오는가

> 회장: "여러 인터넷 정보에서 **주기적으로 취합**해서 가격 가져오면 되잖아.
> 어차피 **정가**로 가져오는 건데."

맞습니다. 다만 **크롤링은 하지 않습니다.** 약관 위반·차단·법적 위험이 있고,
막히는 날 가격이 통째로 사라집니다. 대신 이렇게 합니다.

#### 6.6.1 구조

```
[주 1회 GitHub Actions]
   ↓
1. 카탈로그를 읽고 "가격 확인이 필요한 신발" 목록을 만든다
     · 가격이 없는 것
     · 확인한 지 90일이 지난 것
     · 새로 추가된 것
   ↓
2. 각 신발의 공식 페이지 주소를 붙여 확인 큐(JSON)를 갱신한다
   ↓
3. 가격 커버리지 리포트를 만든다  (전체 N켤레 중 M켤레 확인됨 = P%)
   ↓
4. 변경이 있으면 PR을 자동으로 연다  (main 직접 push 안 함)
   ↓
5. 사람이 공식 페이지에서 확인하고 값을 채운 뒤 merge
```

기존 `refresh-shoe-data.yml`이 이미 1·2·4를 하고 있습니다.
**V4에서 3(커버리지 리포트)과 가격 필드를 더합니다.**

#### 6.6.2 가격 필드 (카탈로그 스키마 추가)

```ts
price?: {
  /** 공식 판매가(정가). 원. */
  listKrw: number;
  /** 실구매 범위. 없으면 정가만 씁니다. */
  streetLowKrw?: number;
  streetHighKrw?: number;
  /** 어디서 확인했는지. 'official' | 'brand-outlet' */
  source: PriceSource;
  /** 언제 확인했는지. YYYY-MM-DD */
  checkedAt: string;
};
```

- **`price`가 없으면 화면에 `가격 확인 중`이 뜹니다.** 필드를 비워 두는 것과 다릅니다.
- `checkedAt`이 180일보다 오래되면 화면에 **`오래된 가격일 수 있어요`** 를 같이 씁니다.
- 기존 무결성 검사의 금지 필드 목록에서 `priceKrw`를 빼고,
  **대신 위 구조를 강제하는 검사를 넣습니다**(정가 없이 범위만 있는 것 금지,
  low > high 금지, 미래 날짜 금지, 0원·비현실적 값 금지).
  → 규칙을 푸는 게 아니라 **더 엄격한 규칙으로 바꾸는 것**입니다.

#### 6.6.3 왜 이게 크롤링보다 낫나

| | 크롤링 | 우리 방식 |
|---|---|---|
| 차단되면 | 가격이 통째로 사라짐 | 기존 값이 그대로 남음 |
| 약관 | 위반 소지 | 문제 없음 |
| 비용 | 프록시·서버 = 월 고정비 | 0원 |
| 틀린 값 | 그대로 나감 | PR에서 사람이 봄 |
| 실시간성 | 높음 | 낮음 (그래서 **기준 시점을 항상 표시**) |

**우리는 "지금 최저가"를 파는 앱이 아니라 "이 신발이 대략 얼마인지 정확히 아는" 앱입니다.**
이게 지킬 수 있는 약속입니다.

## 7. 메트로놈 (새 기능)

회장 지시: **별도 카테고리로, 배경음악과 함께, 러닝에 최적화.**

### 7.1 왜 필요한가

같은 속도로 달려도 발걸음이 빠르고 보폭이 짧으면 무릎 충격이 줄어듭니다.
초보가 가장 쉽게 고칠 수 있는 것이 발걸음 리듬입니다.

### 7.2 화면

```
케이던스

[ 160 ]  [ 170 ]  [ 180 ]      ← 많이 고르는 값 3개 (§4.6)
전체 보기 ▾                     ← 100~200, 5 단위

지금 내 리듬을 모르겠어요  →     ← 30초 재보기 도우미

소리     딸깍 / 낮은북 / 삐 / 진동만
세기     ●●●○○
강박      4박마다 강하게 (켜기/끄기)

천천히 올리기  ⓘ
  5분마다 +2  (지금 165 → 30분 뒤 177)

[ 시작 ]
```

### 7.3 규칙 (안전)

- **한 번에 5 이상 올리지 않습니다.** 갑자기 올리면 종아리를 다칩니다.
- 상한 200, 하한 100.
- "천천히 올리기"는 목표를 **지금 값 +10 이내**로만 잡습니다.
- 처음 쓰는 사람에게는 "지금 리듬 재보기"를 먼저 권합니다.

### 7.4 배경음악과 함께

- 음악을 **끊지 않습니다.** 다른 앱 음악 위에 얹습니다.
- 메트로놈 소리는 음악보다 작게 시작(기본 60%)하고 사용자가 조절합니다.
- 음성 코치와 겹치면 **코치가 우선**입니다. 코치가 말하는 동안 메트로놈을 잠시 줄입니다.

### 7.5 훈련과 연동

- 계획 회차·일회성 훈련 실행 중에도 켤 수 있습니다.
- 구간이 걷기로 바뀌면 **자동으로 잠시 멈춥니다**(걸을 때 케이던스는 의미가 없음).
- 달리기 구간으로 돌아오면 다시 시작합니다.

### 7.6 만드는 방법 (기술)

| 단계 | 방법 | 이유 |
|---|---|---|
| 1단계 | 앱 안에 짧은 클릭 소리 하나를 넣고, **벽시계 기준 자기보정 타이머**로 재생 | 새 의존성 0, OTA로 배포 가능 |
| 2단계 | 1단계에서 박자가 흔들리면, 이미 있는 포그라운드 서비스의 틱을 정밀화 | 화면 꺼짐·주머니 대응 |

- **1단계를 먼저 내보내고 실기기에서 들어 본 뒤** 2단계를 판단합니다.
- 음성 코치에서 배운 규칙을 그대로 적용합니다:
  **"코드가 있으니 된다"로 판단하지 않고, 시간이 흐르는 동안 실제로 나가는지 테스트합니다.**

## 8. 성장 — 알(egg) 대신 무엇을 쓸 것인가

러닝라이프는 알이 부화합니다. 귀엽지만 **내 기록과 상관이 없습니다.**
우리는 **내가 실제로 한 것이 그대로 그림이 되는 방식**을 씁니다.

### 8.1 이번 달 지도

```
   ▁▃▅▂▁ ▇▃ ▁▁▅▇▅▃▁
   7월  ·  움직인 날 14일  ·  212분
```

- 한 칸 = 하루, 높이 = 그날 움직인 시간
- 걷기는 옅은 색, 달리기는 진한 색
- **빈칸을 죄책감으로 만들지 않습니다.** 쉬는 날은 그냥 낮은 칸입니다.

### 8.2 단계 (알 대신)

기록이 쌓이면 지도의 **바탕**이 바뀝니다.

```
1단계  들판      (첫 기록)
2단계  길        (10회)
3단계  강        (30회)
4단계  언덕      (60회)
5단계  산        (100회)
```

- 되돌아가지 않습니다. 한 번 오르면 유지됩니다.
- **쉰다고 잃지 않습니다.** 잃게 만들면 다쳐서 못 쉬는 사람이 생깁니다.

### 8.3 왜 이게 더 나은가

| 알 | 지도 |
|---|---|
| 진행이 추상적 | 내가 언제 뛰었는지 그대로 보임 |
| 부화하면 끝 | 계속 자람 |
| 못 지키면 죄책감 | 쉰 날도 그냥 지형의 일부 |

## 9. 회고 — 이모지 대신 무엇을 쓸 것인가

러닝라이프는 😁🙂😐😮‍💨🥵 5개를 줍니다. 회장이 바꾸라고 했습니다.

### 9.1 바꾸는 이유

- 이모지는 **뜻이 사람마다 다릅니다.** 😐가 "보통"인지 "별로"인지 모릅니다.
- 5단계는 너무 많습니다. 끝나고 숨찬 사람에게 5지선다는 부담입니다.

### 9.2 새 방식 — 말로 고르는 3지선다

```
오늘 어땠어요?

[ 여유 있었어요 ]      말하면서 뛸 수 있었음
[ 딱 좋았어요 ]        조금 숨찼지만 끝까지 감
[ 힘들었어요 ]         중간에 멈추고 싶었음

몸은 어땠어요? (여러 개 고를 수 있어요)
[ 괜찮아요 ] [ 다리 뻐근 ] [ 무릎 ] [ 발목 ] [ 숨이 참 ]

메모 (안 써도 돼요)
```

### 9.3 이 값을 실제로 씁니다 (러닝라이프보다 한 단계 위)

받기만 하고 안 쓰면 의미가 없습니다.

- **"힘들었어요"가 2회 연속** → 오늘 제안이 자동으로 한 단계 낮아집니다
- **"여유 있었어요"가 3회 연속** → 다음 단계 계획을 권합니다
- **무릎·발목이 2회 이상** → "쉬는 편이 좋겠어요" + 보조 프로젝트 "아플 때 판단하기"로 연결
- 저장은 이 기기에만. 진단하지 않습니다.

## 10. 지켜야 할 규칙 (전부 유지)

기존 안전선은 하나도 풀지 않습니다.

- **안전 검증기를 약화시키지 않습니다.**
- 부하는 "뛰는 시간의 합"부터 정합니다.
- 기록이 없으면 하프 이상을 열지 않습니다.
- `start9` ID와 회차 ID를 바꾸지 않습니다. **기존 사용자 기록이 끊깁니다.**
- Production 권한을 늘리지 않습니다(`POST_NOTIFICATIONS` 하나).
- 하프·마라톤은 전문가 검수 전에 공개하지 않습니다.
- **대사를 같은 시각에 두 개 이상 놓지 않습니다.**
- **"코드가 있으니 된다"로 판단하지 않습니다.**
- 새 유료 API 0 · 유료 음성 0 · 광고 0 · 제3자 분석 0 · 새 월 고정비 0
- **경쟁 앱의 문장·훈련표·상표·이미지를 가져오지 않습니다.** 구조와 원리만 배웁니다.

**V4에서 더하는 규칙 (가격·그림 때문에 새로 필요합니다)**

- **가격을 지어내지 않습니다.** 모르면 `가격 확인 중`입니다. 빈 칸도, 추측도 아닙니다.
- **가격에는 항상 기준 시점과 출처가 붙습니다.** 둘 중 하나라도 없으면 화면에 안 냅니다.
- **`최저가`·`최저가 보장`·`정품 보장` 같은 말을 쓰지 않습니다.** 지킬 수 없는 약속입니다.
- **외부 사이트를 크롤링하지 않습니다.** 확인은 공식 페이지에서 사람이 합니다(§6.6).
- **순위를 돈으로 바꾸지 않습니다.** 산식은 앱 안에 공개합니다.
- **브랜드 로고·상표·제품 사진을 그리거나 넣지 않습니다.** 형태와 색만 씁니다(§4.7.2).
- **그림은 전부 벡터입니다.** 사진 파일을 번들에 넣지 않습니다(APK 용량·저작권).
- **제휴 링크·수수료를 넣지 않습니다.** 넣으려면 회장 승인이 먼저입니다.

## 12. 실행 순서 — 5회 반복

회장 지시: **"처음부터 끝까지 반복하면서 업데이트하고 보완하고, 다시 업데이트하고
보완하고, 5번 반복해."** 그래서 한 번에 다 만들고 끝내지 않습니다.
**같은 범위를 다섯 바퀴 돌면서 매 바퀴 실제로 배포합니다.**

### 12.1 다섯 바퀴

| 바퀴 | 이름 | 무엇을 끝내는가 |
|---|---|---|
| **1회차** | 뼈대 | 디자인 시스템 · 탭 5개 IA · 훈련 4칸 분리 · 홈 재설계 |
| **2회차** | 러닝화 (회장 최우선) | 신발 그림 · **가격 필드 + 가격 100% 표시** · 용도/가격대 입구 · 순위 · 홈 순위 · 내 신발 · 가격 파이프라인 |
| **3회차** | 대회·온보딩 | 대회 포스터 · 카드/캘린더 개편 · 온보딩 4단계 · 목표 대회 연동 |
| **4회차** | 습관 | 회고(3지선다+몸 상태) → 오늘 제안 연동 · 성장 지도 · 메트로놈 |
| **5회차** | 다듬기 | 전 화면 재점검 · 성능 · 빈 상태 · 오류 문구 · 실기기 확인 · 최종 배포 |

**2회차를 앞으로 당겼습니다.** 회장이 가장 여러 번 말한 것이 러닝화와 가격이기 때문입니다.
뼈대(1회차) 없이는 러닝화 화면도 조잡해 보이므로 1회차만 앞에 둡니다.

### 12.2 매 바퀴 똑같이 하는 것

1. 순수 로직은 `domains/`에, 화면은 `app/screens/`에
   (`domains/`는 react-native를 import하지 않습니다 — Node 테스트가 돌아야 합니다)
2. **테스트를 먼저 통과시킵니다.** "말이 만들어지는지"가 아니라 "실제로 그렇게 되는지"를 봅니다
3. `npm --prefix apps/mobile test` + `npm run check` 통과
4. PR → CI 초록 → merge
5. **OTA 배포 → 설정 화면의 배포 시각이 배포 로그와 맞는지 확인**
6. 이번 바퀴에서 **무엇이 아직 덜 됐는지** 다음 바퀴 앞에 적어 둡니다

### 12.3 배포는 묻지 않습니다

회장 지시: **"묻지 말고 순차적으로 전부 업데이트해서 완성시켜라.
자고 일어났는데 배포 승인 기다린다는 소리 하면 안 된다."**

→ 이 문서의 범위 안에서는 **merge와 OTA 배포까지 승인된 것으로 봅니다.**
→ 다만 아래는 **여전히 사람 확인이 필요합니다**(회사 규칙, 이 문서가 못 바꿉니다):
   새 유료 지출 · 계정/청구/권한 변경 · 비밀값 · 백업 없는 대량 삭제 ·
   되돌릴 수 없는 마이그레이션 · Play 스토어 계약. 이 문서의 작업에는 하나도 없습니다.

## 13. 완료 기준 (이걸 못 채우면 완료가 아님)

- [ ] 한 탭에서 세로 스크롤 3화면을 넘지 않는다
- [ ] 누를 수 있는 것이 전부 48px 이상이다
- [ ] 한 화면에 주 버튼이 하나다
- [ ] 처음 켠 사람이 **4단계 안에** 첫 회차 시작 버튼까지 도달한다
- [ ] 러닝화 카드에 **그림·용도·정가·실구매 범위·기준 시점·매칭 이유**가 다 있다
- [ ] **가격이 비어 있는 카드가 하나도 없다** (모르면 `가격 확인 중`이 뜬다)
- [ ] 가격 커버리지가 리포트로 세어지고, 그 숫자가 올라가고 있다
- [ ] **홈 아래쪽에 신발 순위 TOP 5**가 있고, 각 줄에 가격이 있다
- [ ] 순위 헤더를 누르면 **산식이 그대로 열린다**
- [ ] 러닝화 첫 화면에서 **가격대로도** 고를 수 있다 (용도와 같은 크기)
- [ ] 신발 그림이 **종류별로 다르게** 보인다 (쿠션·대회용·트레일이 눈으로 구분된다)
- [ ] 대회 카드에 **포스터**가 있고, 목록이 글자만 있지 않다
- [ ] 대회 카드 한 장에 필요한 정보가 다 있다
- [ ] 메트로놈이 **실기기에서 박자가 흔들리지 않는다**
- [ ] 회고 값이 **실제로 오늘 제안을 바꾼다**
- [ ] 성장 지도가 내 기록과 정확히 일치한다
- [ ] 기존 사용자의 `start9` 진행과 활동 기록이 그대로다
- [ ] 모바일 테스트 전부 통과, Production 권한 그대로
- [ ] 배포 후 **설정 → 앱 업데이트 시각이 배포 로그와 일치**

- 러닝라이프 — 회장 제공 스크린샷 (구조·원리만 참고, 문장·표·상표 미사용)

- 러닝화 추천 도구들의 용도별 분류(입문·데일리·장거리·스피드·대회·트레일)와 가격대 필터
- 모바일 온보딩의 점진적 공개(progressive disclosure)와 목표 기반 개인화
- 습관 앱의 이정표(milestone) + 진행 표시 — 다만 **연속 기록(streak)은 쓰지 않습니다.**
  쉬지 못하게 만드는 장치는 러너를 다치게 합니다.
- 가격 비교 서비스들의 표기 방식 — **기준 시점·출처를 반드시 함께 쓰는 관행**만 가져옵니다.
  "최저가" 경쟁은 하지 않습니다. 우리가 지킬 수 없는 약속이기 때문입니다.
- 브랜드 국내 공식 페이지 — 정가·공식 사양의 **유일한 출처**. 그 밖의 값은 쓰지 않습니다.
