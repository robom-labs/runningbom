# 러닝봄 최종 화면 검수 · 2026-10-18

최신 정본은 이 저장소의 인계 브랜치다. 과거 8/197개 상품·예시 피드·고정 이미지 상자 기준 리포트를 대체한다. 웹 UI와 실제 Play 출시 판정은 구분한다. 전체 운영/출시 관문은 `../../HANDOFF.md`, `../../outputs/release-review/index.html`을 읽는다.

## 최종 변경과 실제 검수

- 큰 장비 검색창과 메인 문답 진입을 삭제했다. 브랜드·가격·정렬은 한 줄 44px 버튼, 종류는 기존 Carousel의 가로 한 줄이다. 390px 화면에서 첫 신발 grid 시작은 y=343.3px이다. `qa/final-production-gear-390.png`.
- 대회 이미지가 88px인데 이전 compact grid가 68px로 덮어써 제목과 20px 겹치던 문제를 수정했다. 실제 320px/390px/1400px DOM에서 겹침 false를 확인했다. 사진/제목/보조정보/날짜 푸터가 각 칸을 유지한다. `qa/final-mobile-race-cards-390.png`, `qa/final-race-list-320.png`.
- 대표 사진은 고정 큰 상자를 없애고 원본 비율로 보여준다. PC 사진의 원본 비율 2.064516, 렌더 비율 2.064530으로 오차는 반올림 수준이다. 포스터·로고는 작은 옆 칸, 가로 배너는 원본 높이를 쓴다. 상세는 intrinsic 높이이며 미디어가 없으면 생략한다. `qa/final-production-home-390.png`, `qa/final-desktop-home-1400.png`.
- 달력은 7개 동일 폭 날짜/개수 칸과 별도 날짜별 카드 목록이다. 320px에서 헤더/날짜 열 폭 38.05–38.10px, document 폭 320px를 확인했다. 날짜 선택 후 device-screen scrollTop=0, 헤더 y=0을 유지했고 ‘달력’ 복귀도 동작했다. `qa/final-calendar-320.png`.
- 768px 신발 3열(각 229.3px), 1400px 신발 4열(각 268px), PC 메뉴 206px. 작은 화면은 2열이다. 화면 폭별 가로 문서 넘침은 관찰하지 못했다. `qa/final-tablet-gear-768.png`, `qa/final-desktop-gear-1400.png`.
- 10~20만원 선택은 실제 24모델/4브랜드로 좁혀졌으며 해외 통화·가격 미확인을 포함하지 않았다. 출시 예정으로 전환하자 이전 가격/브랜드 필터가 초기화되고 실제 발표 2모델이 나왔다. 가격 미확인 행은 생략됐다. `qa/final-price-filter-390.png`, `qa/final-upcoming-390.png`.
- 소통의 실제 빈 DB, 주제·광역 지역 탐색, 프로필/내 일정, 비활성 간편로그인 안내를 확인했다. 가짜 사용자나 게시물로 빈 상태를 채우지 않았다. `qa/final-mobile-community-390.png`, `qa/final-mobile-personal-390.png`, `qa/final-production-login-390.png`.
- 하단 메뉴는 둥근 흰 도크, 24px 아이콘, 청록 선택 pill, 12px 라벨과 안전 영역을 유지한다. 긴 카드 제목/거리는 두 줄, 날짜·상태는 한 줄이다. 320px 필터 도구 줄바꿈은 의도된 반응형 배치다.
- 고객 화면에서 출처/수집 시각/공식몰·공식 발표 설명을 제거했다. 데이터의 URL·원본 해시·정밀도·검토 상태는 내부에 남겼다. 제품 구매/대회 접수 링크는 유지했다.

## 소스 시안과 변경 의도

사용자가 선택한 밝고 사진 중심 1번 시안은 `../../docs/design/selected-design-1.png`로 함께 인계했다. 흰색·남색·청록, 제목 대비, 둥근 카드와 5개 메뉴를 유지했다. 이후 사용자가 요청한 실제 미디어·정보량·글자 확대·반응형·장비 밀도·소통을 반영했으므로 원래 예시 문구/이미지/픽셀과 일치한다고 주장하지 않는다. 같은 가로 390px의 비례 비교는 `qa/final-design-comparison-1x.png`다. 원본의 기기 프레임/상태바와 실제 웹 콘텐츠 영역은 서로 다른 검수 범위다.

## 자동 검수와 실제 한계

- 루트 125 + 웹 27 + 네이티브 1204 = **1356개 테스트 통과**. 웹·네이티브 타입 검사, 앱 설정, 정적 데이터, 보호 런타임 28개, 웹 production build, Android Hermes export 통과.
- 실제 DB 회원/채팅/권한 14 + 탈퇴 6 + 피드 6 = **26개 통과**, 테스트 자료 롤백.
- production 웹을 별도 로컬 서버에서 실행해 홈·장비·소통·회원 진입을 확인했다. 최종 production 세션에서 error/warn 콘솔 항목은 관찰되지 않았다. 개발 서버 재연결/의존성 캐시 구간에는 이전 HMR/React hook 오류가 있었으며 최종 별도 production 실행에서는 재현되지 않았다. 전체 환경의 오류 0건을 보장하지 않는다.
- 기존 기기 프레임/키보드/상태바 파일 28개는 바꾸지 않았다. Git 인계에서도 보호 파일은 원본 바이트를 보존해 Mac에서 CRLF/LF 변환 때문에 해시가 깨지지 않게 했다.
- Android export 112.97 MiB는 실행 번들·원본 자산이며 **서명 AAB나 설치/실기기 시험이 아니다**. 네이티브는 웹과 별도 UI이므로 화면 대조와 Play 사전 출시 검수는 남았다.
- 공개 대회 87 중 확인된 미디어 70, 원본 전체 미디어 93. 미확인 이미지를 생성하지 않았다. 러닝화 200모델/15브랜드, 웹 원본 186/네이티브 번들 원본 171, 출시 예정 2개.
- 운영 수집 도구 audit은 0건, 네이티브 production guard는 node-forge/braces **High advisory 2건**으로 실패한다(npm audit 전이 항목 17개). 강제 downgrade·무근거 예외를 적용하지 않았다.
